# Desktop VNC engine construction

The root now registers this Android library for canonical construction checks. It does not yet add an Activity or change either app's dependencies, and registration does not establish an adopted Desktop capability. The [private product entry](../../../../docs/03-platform/googlebook/vnc-product-private-entry.md) controls current integration boundaries. At initial source-only freeze01, no module compile, Android Lint, JVM owner tests, native namespace build or device operation had run. Subsequent build and execution evidence is frozen separately; this description does not certify those checks.

`VncEngine` owns a single attempted connection. Supply an explicit immutable numeric endpoint, profile identifier, exact32-byte leaf SHA-256, port and duration10–600seconds. Only the retained patched VeNCrypt19/X509Plain262/TLS>=1.2 route is used. Exact-leaf pin and validity are not ordinary CA/name trust. The public constructor uses Android's numeric parser; the engine checks the owning app's API37 local-network permission before native allocation. The app must own actual permission UX, admission and credential/trust decisions. Transferred nonempty canonical UTF-8 username/password arrays are disposed on rejection and immediately after native creation; temporary decoder character storage is explicitly wiped. No credentials, config, defaults, profiles or journals are persisted here.

All JNI calls execute on the retained owner worker. Input methods return Java queue admission only; native write high-water marks are diagnostics, not per-input host acknowledgments. Stop disables local input immediately. A connected deliberate stop queues the native tracked key/button release and waits at most750ms for its write result or actual terminal status before cancellation. Release rejection/failure/timeout is recorded truthfully and does not prevent cancel/join/free. Initialization/terminal paths skip inapplicable releases. Native join waits at most5000ms; failed join or free retains the nonzero handle and process lease as `CLEANUP_UNCERTAIN`. An explicit `retryCleanup()` may retry retirement; it never starts a second connection. Callback and UI threads never perform the join.

Callbacks are fenced by the original attempt and handle. `takeLatestFrame()` transfers one complete owned RGBA frame to the presentation layer, replacing the previous pending complete frame without dropping dependent decoder updates. Each frame is at most32MiB. The engine retains one pending frame; the caller must retain at most one presented frame. Native framebuffer, scratch and resize overlap are additional allocations. `FIRST_FRAME` means callback delivery, not conversion, drawing or visible playback. No UI, discovery redesign, fullscreen, relative-input, clipboard, audio, negotiated resize/encoding or sustained-session claim is included.
