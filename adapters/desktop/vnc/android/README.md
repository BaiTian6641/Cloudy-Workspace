# Desktop VNC engine construction

This unregistered Android library is a source candidate, not an adopted Desktop capability. It does not add an Activity or change either app's dependencies. Parent review and isolated compilation/native packaging are required before adoption. At initial source-only freeze01, no module compile, Android Lint, JVM owner tests, native namespace build or device operation had run. Subsequent build and execution evidence is frozen separately; this description does not certify those checks.

`VncEngine` owns a single attempted connection. Supply an explicit immutable numeric endpoint, profile identifier, exact32-byte leaf SHA-256, port and duration10–600seconds. Only the retained patched VeNCrypt19/X509Plain262/TLS>=1.2 route is used. Exact-leaf pin and validity are not ordinary CA/name trust. The public constructor uses Android's numeric parser; the engine checks the owning app's API37 local-network permission before native allocation. The app must own actual permission UX, admission and credential/trust decisions. Transferred nonempty canonical UTF-8 username/password arrays are disposed on rejection and immediately after native creation; temporary decoder character storage is explicitly wiped. No credentials, config, defaults, profiles or journals are persisted here.

All JNI calls execute on the retained owner worker. Input methods return Java queue admission only; native write high-water marks are diagnostics, not per-input host acknowledgments. Stop disables local input immediately. A connected deliberate stop queues the native tracked key/button release and waits at most750ms for its write result or actual terminal status before cancellation. Release rejection/failure/timeout is recorded truthfully and does not prevent cancel/join/free. Initialization/terminal paths skip inapplicable releases. Native join waits at most5000ms; failed join or free retains the nonzero handle and process lease as `CLEANUP_UNCERTAIN`. An explicit `retryCleanup()` may retry retirement; it never starts a second connection. Callback and UI threads never perform the join.

Callbacks are fenced by the original attempt and handle. `takeLatestFrame()` transfers one complete owned RGBA frame to the presentation layer, replacing the previous pending complete frame without dropping dependent decoder updates. Each frame is at most32MiB. The engine retains one pending frame; the caller must retain at most one presented frame. Native framebuffer, scratch and resize overlap are additional allocations. `FIRST_FRAME` means callback delivery, not conversion, drawing or visible playback. No UI, discovery redesign, fullscreen, relative-input, clipboard, audio, negotiated resize/encoding or sustained-session claim is included.

The parent may run `python3 tools/prepare_desktop_vnc.py --prepare --output .cache/vnc-product-engine-01/prepared` once native-build ownership is available. `--stage` stages imports/recipe without compilation and deliberately cannot satisfy `--check`. The helper verifies the selected auth-idle-01 receipt, exact security patch/original adapter, static patched archive/matching headers, JPEG and SSL closure; it generates only a JNI namespace substitution and compiles only the JNI layer. It does not rebuild or retest LibVNCClient/OpenSSL/JPEG, acquire dependencies or substitute an unpatched shared client. Original probe sources and receipts remain unchanged. A failed stage/build preserves its fresh output without an accepted final receipt. `preBuild` requires `--check` of the published namespace-port receipt, exact exports, ELF alignment/dependencies and output hashes.

The pure Python helper controls execute separately from native/Android checks, including process-group timeout ordering and narrowly scoped NDK tool-link rules. The eight owner JVM cases are test-only backend/platform seams; initial source freeze recorded them unrun, and subsequent execution requires its separate result receipt; they are not JNI or server evidence. Parent future checks should compile debug/release, run these focused owner methods and Android Lint in an isolated graph, then one explicit real fixture for native load, protected connect, owned frame, deliberate release/stop and observed join/free plus changed trust/cancellation boundaries. No unchanged upstream battery is needed.

D16 permits compatible open-source Desktop distribution work. The selected LibVNC/miniLZO GPL-2.0-or-later option, JPEG notices and OpenSSL Apache-2.0 materials are carried as construction inputs. The exact combined release license/corresponding-source closure remains a parent review; this library does not grant a repository license or make the existing notices final release approval.
