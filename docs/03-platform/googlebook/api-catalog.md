## Revision 02 file publication boundary

Revision 02 adds **API33**, the upstream SFTP file-publication boundary: `SSH_FXP_STAT`, `SSH_FXP_OPEN`, `SSH_FXF_CREAT`, `SSH_FXF_EXCL`, `SSH_FXP_RENAME` and `posix-rename@openssh.com`. [OpenSSH's extension](https://raw.githubusercontent.com/openssh/openssh-portable/master/PROTOCOL) has old/new path fields and no expected-version condition. The [historical v3 draft](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-02) is an expired protocol reference, not a newly released Googlebook API. P2-S7 must qualify the actual server/engine, exclusive creation, concurrent writer between check and publication, and ambiguous completion. A metadata check followed by rename cannot itself promise conflict-free replacement; retain staging and expose only supported publication choices.

## How to keep the catalog useful

For an implementation change: find the tracker entry, inspect the official signature and release notes, fill the exact SDK/library version, compile a minimal probe, record device evidence, and update the linked stage. Use distinct statuses for documented, experimental, roadmap, unavailable, and unknown. No successful HTTP response can promote an API to device-qualified.

## P0-S2 finite HTTPS transfer experiment

The [transfer contract](p0-s2-transfer-probe-contract.md) refines API39/API41 using G82–G97 and re-reviewed G21/G22. Both reviewed versions passed compilation, Android Lint and 61 JVM tests; see the [review](../../06-validation/2026-10-15-transfer-probe-review.md). The [0.4.0 preflight](../../../qualification/results/P0-S2/2026-10-15-transfer-preflight.md) remained queued with CONNECTIVITY unsatisfied under a Wi-Fi/VPN application network, then was durably cancelled before worker claim with zero bytes. The separate [0.4.1 lifecycle evidence](../../../qualification/results/P0-S2/2026-10-15-transfer-lifecycle.md) records actual payload and cancellation observations under its corrected source/APK identity. Both API records remain **untested** overall; CAP-PLATFORM is `experiment`, and no capability is supported.

- **Scheduling and ownership:** API34 UIDT uses a nonexported `JobService` protected by `BIND_JOB_SERVICE`, with `RUN_USER_INITIATED_JOBS`; network constraints additionally require `ACCESS_NETWORK_STATE` on API34+. `canRunUserInitiatedJobs()` checks permission, not visibility. Start only through the visible explicit action and inspect `schedule()` result/exception. Persist a claimed attempt before network I/O; reject automatic replay after process loss.
- **Assigned route:** use API28 `JobParameters.getNetwork()` with API21 `Network.openConnection(URL)`. Reviewed 0.4.1 uses API21 `NetworkRequest.Builder.removeCapability(NET_CAPABILITY_NOT_VPN)` while retaining the Wi-Fi/Ethernet transport alternatives and other defaults. It permits the user's existing VPN network when its advertised transports match, without selecting an underlying network or changing VPN policy. INTERNET/VALIDATED/NOT_METERED remain omitted; null/changed assigned network interrupts. A VPN can advertise multiple physical transports, so matching Wi-Fi is not proof of Wi-Fi-only packet routing. API30 `NetworkRequest.canBeSatisfiedBy` can diagnose capability matching, not endpoint reachability or scheduler readiness. G95's pinned upstream default-per-UID selection explains the observed mismatch but is not the HP build source. API35 `NET_CAPABILITY_LOCAL_NETWORK` describes address-advertising networks, not ordinary LAN-server reachability.
- **Notification and cancellation:** supply `setNotification()` within ten seconds on every run. Show API33 notification denial separately and record API24 package/API26 channel visibility without blocking scheduling. Always supply the required job notification; retain native-screen Cancel when the notification action is hidden. An immutable explicit Cancel PendingIntent needs unique attempt identity. Invalidate work promptly on stop, return false for no retry, and never let an obsolete action or worker completion overwrite a newer attempt.
- **Permission and TLS:** runtime37/target37 direct LAN requires the API41 grant before access; retain denial/revocation separately from routing and TLS failures. A scoped `TrustManagerFactory`/`SSLContext` can trust the fixture CA through `HttpsURLConnection.setSSLSocketFactory`, while unchanged platform hostname verification authenticates the URL host. Reject incorrect trust and hostname; no global TLS override or accept-all fallback.

The bounded 0.4.1 observations include a 67,108,864-byte completed download with an independently exported matching SHA-256, recreation/minimize/return during that attempt, native-screen cancellation with stable partial bytes, and notification cancellation while the transfer Activity was hidden followed by a saved terminal state in the same process. Wrong-CA configuration alone produced `SSLHandshakeException`, zero bytes and no payload file. Stopping the fixture midstream produced `ProtocolException` and retained stable partial bytes; restoring the fixture did not automatically retry. A fresh explicit attempt subsequently completed another independently verified 67,108,864-byte file.

A package-scoped injected `SIGKILL` then terminated the process during claimed work. The historical journal still said `running` until relaunch; a new process reconciled the same attempt to `interrupted` with `new-process-unfinished-attempt`, retaining the same 5,177,344-byte partial file and hash. A later observation more than 64 seconds after recovery remained unchanged, with no new host request and no probe job observed. All eight attempt slots were retained, so capacity also prevented a further Start; this is bounded no-replay evidence, not a post-recovery Start-eligibility test or natural low-memory/Task Manager behavior.

These observations do not establish wrong-hostname rejection, permission revocation, assigned-network-change handling, Task Manager stop, physical input, indefinite background reliability or arbitrary power-loss durability. Cancellation-request readback is distinct from worker exit and saved terminal cancellation. Finite HTTPS evidence also does not qualify SFTP overwrite/publication recovery, continuous SSH/desktop service classification, general VPN/provider behavior or production certificate policy.

### API07 native focus correction

The 0.7.1/code10 probe requests focus once during the native Connect action, after attaching the WebView and rendering controls, before renderer startup. `View.requestFocus()` and the implemented focusability/query methods are available from API1; no additional minSdk35 guard is needed. A rejected request shows a separate tap hint while preserving connection status. `Activity.getCurrentFocus()` may return null, and `View.hasFocus()` includes descendant focus; the details dialog reports only this native observation.

The [terminal run](../../../qualification/results/P0-S3/2026-10-15-terminal-probe.md) and [manifest](../../../qualification/results/P0-S3/2026-10-15-terminal-probe-manifest.json) retain the 0.7.0 failure and scoped 0.7.1 result (buildRef `60908d62-c573-4c4b-8b0e-910e5863197e`): paced injected echo/control bytes worked without a terminal tap after Connect. The recorded rapid ADB input duplication remains unresolved; the focus correction does not qualify input integrity. Physical keyboard, native IME and bulk-paste qualification remain pending. API07 stays untested for its full scope; DOM focus and this observation do not establish those outcomes. Official sources: G24, G25 and G117.
