# Native stream playback integration entry

**2026-10-15. Status: next integration contract; current 0.1.6 is a build-only checkpoint, not playback/runtime qualification.** This entry records the reviewed minimum UI/lifecycle integration for the existing real `PlaybackController` and pinned Moonlight engine. It does not authorize a device/server run or promote CAP-STREAM. The [native-stream adoption entry](native-stream-adoption-entry.md) and [key-provider entry](native-stream-key-provider-entry.md) retain their source, licensing and identity boundaries.

## One operation and one original authorization deadline

Add playback to the existing `StreamProbeViewModel.Operation` and process-wide `StreamOperationLease`, alongside identity, native load and pairing. Playback must not introduce an independent admission path. The operation owns an immutable approved profile, the existing identity attempt, controller, render-target generation and durable journal. All identity/pair/playback entry actions remain disabled while that operation or its cleanup owns the lease. The playback controller's static native-session guard is additional protection, not a replacement for global admission.

Before prompting, read and freeze the approved numeric LAN peer, distinct HTTP/HTTPS/RTSP ports, exact app ID, public server leaf certificate and SHA256 pin. `PlaybackProfile` validates numeric IPv4, bounds and certificate identity/validity; unicast syntax alone does not establish an approved LAN route. Use the private controlled profile route, not remote UI text or a network-discovered replacement certificate. An already-paired playback action does not automatically pair, retry, delete identity or regenerate keys.

Require a fresh explicit `DEVICE_CREDENTIAL` prompt and a token-matched result of authentication type 1. Reuse the actual original callback's `authenticatedAtElapsedMillis` through `store.qualify(...)`, `store.provider(op.attempt)` and `PlaybackController` construction. The combined operation has at most **30 seconds from that original callback**, including qualification, surface readiness, connection setup and playback. Never reset the timestamp after any intermediate step, extend authorization automatically, sleep/retry signing, weaken key policy or substitute a software key/provider. A delayed or stale callback must fail before crypto/network admission.

The guard checks operation/attempt identity, foreground ownership, cancellation, uncleared ViewModel, local-network permission and original authentication age below 30 seconds. Check immediately before controller publication, then again after publication and before `run()` so cancellation cannot escape between those steps. The controller/lease retains its own deadline checks. Each finite preview is a new explicit operation with a new system authorization; no observer, restored state or process startup may replay it.

## TextureView and actual retirement

Use native `TextureView`/`SurfaceTexture`/`Surface` presentation. Frames stay in the decoder and native rendering path; no video bytes or frames cross a general UI/JavaScript bridge. The Activity creates the render target on the main thread and binds it to the captured operation and surface generation. `PlaybackController.run(Activity, Surface)` runs on the serialized worker; it does not take ownership of or release the caller's Surface.

On `onSurfaceTextureDestroyed`, signal the captured controller's `surfaceLost()` and return false so TextureView does not release the SurfaceTexture beneath an active decoder. This uses the [official API14 destruction contract](https://developer.android.com/reference/android/view/TextureView.SurfaceTextureListener#onSurfaceTextureDestroyed(android.graphics.SurfaceTexture)): returning false makes the client responsible for release. Retain the Surface and SurfaceTexture in the operation until `retired()`/`cleanupComplete` confirms actual decoder/native retirement, then release them through a main-thread ownership handoff. A stale destruction callback must never cancel or release a newer render target.

For this increment, surface destruction during configuration recreation also cancels playback. A recreated Activity may display stopping/cleanup-pending state, but must not start a replacement, replay the operation or rebind the old decoder to its new TextureView. The current controller has no surface-rebind API. Its original Activity reference remains retained only for the native/decoder lifetime and must be cleared after cleanup. Prompt recreation continues to reattach its existing token without calling authenticate again. Focus loss alone is not background cancellation; actual last-window backgrounding requests cancellation without blocking main.

Do not reuse the ViewModel's unconditional operation retirement for playback. Request stop promptly, execute native cleanup on the serialized worker, and release global admission only after native retirement, caller-owned render-target release and successful terminal journal persistence. `CLEANUP_PENDING` or a hung cleanup keeps the controller, surface and admission owned and the UI blocked. A bounded explicit cleanup retry may operate on that same owner. `onCleared()`, generic cancellation, evidence failure and `finally` blocks must not release ownership merely because a worker returned or cancellation was requested. No identity deletion/new pairing may overlap pending native cleanup.

## One native playback lifetime per process

The current native core's common C asynchronous termination thread is detached. The bounded integration therefore permits **one native playback lifetime per process**. Once native playback has been used, require a fresh process before another native playback attempt, even if local cleanup reports success. Do not reset or bypass the process guard. This is an explicit qualification limitation, not a restart/reconnect capability or proof that detached callbacks cannot outlive surrounding state.

Process restart does not resolve unfinished durable evidence or host application state. Reconcile the prior operation first, then require a new explicit action and fresh credential callback; never replay a saved launch. The exact first-use/guard boundary must be source-bound in the controller and tests so native entry cannot race a second admission.

## Durable network-operation evidence

Reserve an atomic, read-back-verified journal with `closed=false` before any playback network/native side effect. Pairing and playback must both check prior records across their network-operation journals. Malformed, unfinished or evidence-unavailable records block new network attempts. Process-local guards alone do not survive process death. An explicit reconciliation records local retirement and actual/unknown host state without automatically launching, unpairing or terminating a remote application.

Set `closed=true` only after actual cleanup and caller-owned surface retirement. The existing generic closed helper, which considers cancellation/prompt state, is insufficient on its own. Persistence failure must leave admission blocked and the operation unfinished; it cannot produce a success/completion claim. Retain original authorization timestamp, requested/result authentication type, bounded controller phase/failure/stop reason and cleanup outcome without URL/query, credential or peer-text logs.

Replace generic zero-valued evidence fields for playback. Record actual decode-unit submissions, released output buffers and rendered-frame callbacks separately, alongside actual format/dimensions, codec identity and hardware report when available. They are different observations; none alone proves visible delivery, latency or hardware performance. The [API23 rendered callback](https://developer.android.com/reference/android/media/MediaCodec.OnFrameRenderedListener) can be delayed/batched and its API34+ guarantee requires the codec still executing at dispatch. The [API29 hardware flag](https://developer.android.com/reference/android/media/MediaCodecInfo#isHardwareAccelerated()) is manufacturer-supplied metadata, not a benchmark. Do not inherit `decodedFrames=0` or `hostConnections=0` from a generic non-network record after real playback work.

## Small implementation and acceptance boundary

The minimum UI is a native render view, explicit authorize/preview action, explicit stop action, sanitized phase/counter text and honest cleanup-pending/process-restart-required state. Identity, pairing and playback share the same immutable attempt ownership. Keep existing desktop insets, system captions, font scaling and accessibility behavior.

Focused authored tests should cover stale prompt/surface generations; cancellation crossing controller publication; original authorization expiry without extension; surface ownership retained through cleanup; cleanup-pending blocking all new operations; one native lifetime per process without guard reset; and unfinished pairing/playback records blocking both network lanes. These tests do not simulate successful streaming as qualification.

The integration leader must review source, build and finite device/controlled-server evidence before accepting runtime behavior. Current 0.1.6 compilation does not prove network startup, decode, presentation, audio, input, cancellation or host-session reconciliation. No device, frame-delivery, latency, 3D, performance or general streaming capability pass is claimed here. Console/Desktop remain independently scoped, and ordinary SSH retains its independent delivery path.
