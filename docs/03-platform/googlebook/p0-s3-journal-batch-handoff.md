## Source and API constraints

The installed 0.6.0 source binds to `af9deaed594fe53fbe52c4825a2e3e96a0e8fd83`. `SshRuntime.refresh()` loads history and trust only when its state is absent; a living runtime can overwrite an externally replaced file with its cached state. `SshJournal.read()` returns empty history **and empty trust** if both its base and backup are absent. The schema-2 codec accepts an empty attempt list with the existing trust map. Its writer creates current process/revision metadata and does not retain an extra batch-lineage field. Keep lineage in a separate private maintenance manifest.

The official [AtomicFile contract](https://developer.android.com/reference/android/util/AtomicFile) (source G50, rechecked today) provides its constructor and read/write APIs from API 17 and requires caller-controlled exclusion; it supplies no file lock. It also handles old backup files. External maintenance must therefore happen with the package stopped and with no unexplained `.bak` or `.new` file. The fallback for uncertainty is to preserve all copies and stop, not choose a presumed latest file. Qualification must demonstrate exact archive/readback and restoration; it must not claim power-loss durability of a multi-file maintenance sequence.

The official [ADB activity-manager reference](https://developer.android.com/tools/adb#am) (G31, rechecked today) documents package-wide `am force-stop`. This is a debug command, not a lifecycle API for the product. Before use, inspect the connected device's help and establish the selected package/user scope. The previous `stop-app` experiment allowed a process to return; its outcome cannot establish a quiet maintenance interval.
