## Android and dependency constraints

Its static initializer disables automatic BC registration. This does not certify any algorithm or Android API level. The existing **`AndroidConfig` is unsuitable as an unreviewed shortcut**: the pinned source attempts SpongyCastle registration and selects Ed25519, legacy ssh-rsa and ssh-dss key algorithms. ## Bounded real qualification sequence

1. **Adoption/compile prerequisite.** Record the diagnostic adoption decision and reviewed dependency graph, exact checksums/notices and modern crypto policy. Build with the pinned Android toolchain, inspect the actual packaged graph and run relevant unit tests. Failures become bounded findings; a passing build is not protocol qualification.
2. **Real host fixture.** Establish the scoped OpenSSH daemon with private generated identities and a dedicated test directory. Record exact server version, effective authentication/forwarding settings and host-key fingerprints. Verify listener cleanup. Keep the app's actual network route distinct from earlier shell ICMP or HTTPS results.
3. **Trust and authentication.** Demonstrate unknown-host rejection, deliberate enrollment of the independently known fixture identity, successful key authentication, wrong-key denial and same-endpoint changed-host-key rejection. Record whether credentials were offered after trust failure; they must not be. Cancellation while awaiting trust must leave no authenticated work running.
4. **Finite exec and PTY.** Run a fixed harmless byte-producing command with a known exit code. Separately allocate a PTY, query server-observed size, change it and observe the new size. Bound output, deadlines and cleanup. No terminal renderer or custom host agent participates.
5. **SFTP integrity and no-clobber.** Generate a finite payload, upload through explicit exclusive creation, read it back through SFTP and independently match length/SHA-256. Attempt the same creation against a retained sentinel and verify collision plus unchanged bytes. Record negotiated protocol/extensions; test supported rename semantics separately under the publication contract.
6. **Cancellation/interruption.** Cancel a larger real transfer, interrupt the fixture and exercise explicit retry. Retain partials and a durable journal; distinguish failure from publication-unknown. Do not replay destructive publication automatically. Activity recreation, process loss and LAN revocation need their own SSH/SFTP evidence; HTTPS results cannot supply it.
7. **Direct-channel/jump follow-up.** Use a real direct channel to a second explicitly configured SSH endpoint, with separate host-key verification/authentication and teardown. A same-machine pair can test protocol composition while remaining narrower than a remote multi-host/network claim.
8. **X11 follow-up.** First prove actual channel requests and rejected wrong-cookie traffic using the selected engine hooks. P0-S7 must subsequently qualify the local X server/broker, remote xauth, simultaneous isolated trust contexts and separate native application windows. An accepted channel or single X desktop does not satisfy that requirement.

Start with foreground, finite work and explicit cancellation. Do not add a generic SSH foreground-service type or relabel SSH as media playback to obtain background persistence. Consult the [operation lifetime note](p0-s2-operation-lifetimes.md) before extending duration or behavior.

`DefaultSecurityProviderConfig` disables SSHJ automatic BC registration through static, process-wide SSHJ configuration. Select and initialize that policy before constructing any `SSHClient`; do not treat it as isolated to one connection or modify Android's global provider list.

## Acceptance and next handoff

The first deliverable is a real native SSH/SFTP probe plus an engine investigation record: exact source/APK/engine/backend identities; trust/auth outcomes; negotiated algorithms; exec/PTY bytes; SFTP length/hash/collision evidence; cancellations/interruption results; and remaining limitations. Collect raw private artifacts separately and publish only sanitized projections/hashes. Review source, dependency notices and evidence independently before changing any outcome.

CAP-SSH and CAP-TERMINAL remain separate. Transport/PTY success cannot establish exact-byte paste, CJK IME/preedit, wide-cell/emoji rendering, selection, accessibility, latency or physical keyboard/mouse behavior. The pinned local renderer and actual physical desktop inputs have their own P0-S3 cases and adoption result. No investigation result alone completes product Console, Desktop, X11 or the P1-S4 distribution gate.

The next bounded exec/PTY and active-owner increment is specified in the [follow-up handoff](p0-s3-exec-pty-followup.md), including pinned symbols, separate fixture restrictions, build-provenance preservation and the deliberate remaining-attempt order.
