## Real SSH and controlled host route

Reuse native trust-before-authentication, algorithm policy, LAN admission, worker ownership and independent socket cancellation. After explicit native admission, use the pinned SSHJ `startSession`, `allocatePTY`, `startShell`, channel input/output streams and `Shell.changeWindowDimensions` interfaces (R93–R96, R98). Propose `TERM=xterm-256color` with actual fitted dimensions and a verified UTF-8 host locale. A normal shell needs reviewed terminal modes; the earlier fixed protocol's forced dispatcher, `ECHO=0` and `ONLCR=0` must not silently become interactive-shell defaults. A shell has no public SSHJ exit-status getter; distinguish stream EOF, transport loss and explicit disconnect honestly.

Prepare a separate temporary host fixture policy. Keep historical SFTP/exec configurations and evidence immutable. Use a dedicated key, a fixed ordinary shell invocation without user startup files, and a private disposable working directory; retain no-forwarding/no-user-rc restrictions and explicitly enable PTY. Validate the actual OpenSSH configuration and observe listener/helper cleanup. A working directory and forced shell are **not a sandbox**: commands still execute with the fixture account's authority. Use a dedicated restricted account/container if confinement is needed; do not describe a directory as filesystem isolation. The implementation owner must review this real command-execution boundary before starting the fixture. Never evaluate `SSH_ORIGINAL_COMMAND` as shell text. R18/R97 define server policy, not proof that this proposed fixture exists.

The operator should be able to type into a real shell and run a real available TUI. A small input-byte capture program invoked inside that shell supplies controlled input evidence; it is not the application's implementation. Ordinary product SSH must continue to need no custom host agent or forced dispatcher.

## Byte transport, flow control and lifecycle

Use a dedicated versioned binary terminal envelope with immutable attempt/attachment identity, stream sequence and validated lengths. Permit only terminal input/output, resize, readiness and acknowledgment operations. No credentials, SFTP payloads, arbitrary methods, host-control messages or video share this channel. WebView API calls occur on their required thread; callbacks validate and enqueue bounded work without network I/O on the UI thread.

Proposed initial tuning limits are chunks up to **16 KiB**, **256 KiB** outstanding output with a **64 KiB** low-water mark, and **64 KiB** queued input. These are implementation limits to test, not measured performance. Reserve capacity for a whole bounded paste before sending any of it; refuse oversize paste visibly. Apply backpressure to native channel consumption and bound the posting queue as well as xterm's pending writes. On an unresponsive/destroyed renderer, stop admission and abort explicitly rather than silently discarding bytes or retaining an unlimited queue. Define a finite renderer-readiness/acknowledgment deadline in the implementation review.

Pass output as `Uint8Array` to `terminal.write(data, callback)` and acknowledge only after its parser callback. Do not decode each native byte chunk independently: UTF-8 codepoints can span chunks. The callback establishes parsing, not pixel presentation or latency. Upstream documents that uncontrolled writes can overflow and discard data (R104/R105). Encode `onData` text as UTF-8 once; `onBinary` is a byte-valued string for non-UTF-8 mouse reports and needs its own direct byte conversion. Do not forward `onKey` or native key events a second time. Preserve terminal-generated query replies through the same bounded input path without mistaking them for physical typing.

Use `ResizeObserver`/fit results and bounded native resize work; confirm dimensions from the actual remote PTY. Coalesce pending resizes, not input bytes. Retain native cancellation independently of a blocked read and do not release the worker until cleanup completes. Initially retain visible-owner-only admission; no foreground-service permission is justified by choosing a renderer. Renderer loss invalidates its generation, stops input and interrupts the session. Recreate only on explicit action until a separately reviewed terminal-state reconstruction exists; never replay keystrokes or commands. Activity/process/renderer loss are different cases. Existing 0.6.0 ownership evidence does not qualify this new WebView lifecycle.

## Source-grounded implementation split

Read-only review of the actual 0.6.0 code confirms that the first terminal should be a separate `Terminal*` lane. `SshOperation`, `SshState`, `SshConfigSpec` and `SshEngine` deliberately enforce finite operations, sentinel-bearing configuration and fixed protocol deadlines. Do not add an interactive operation to that enum or populate fake sentinel fields. Preserve the existing SSH diagnostic and its history.

| Ownership | New source and concrete responsibility |
| --- | --- |
| Configuration and history | `TerminalConfig`, `TerminalState`, `TerminalJournal` and a bounded codec: strict typed endpoint/configuration, explicit trust enrollment, session/build/process/attachment identities, bounded lifecycle events and byte counters. |
| Native transport | `TerminalTransport`: real SSHJ authentication and ordinary PTY shell, independent socket cancellation, separately bounded input writer, output/stderr consumption, resize and helper cleanup. Extract only the existing unchanged algorithm policy and bounded key-file reader into small shared helpers. |
| Renderer and byte flow | `TerminalFrame`, `TerminalFlow`, `TerminalWebViewBridge` and authored HTML/JS/CSS: binary envelope validation, origin/attachment fencing, whole-input admission, output credit and xterm integration. |
| Parent integration | `TerminalRuntime`, `TerminalActivity`, application/navigation/resources/manifest, dependency/assets/build changes, reviewed host fixture and device qualification. Freeze exact interfaces before parallel code edits. |

Use independent `files/terminal-config.json`, `files/terminal-client-key` and `files/terminal-journal.json`. The new runtime must not write or migrate `ssh-journal.json` or silently import its trust. First connection stops before authentication on unknown trust; native acceptance must persist successfully, and a separate explicit Connect starts authentication. Reuse the actual `SshTrust`, `SshBuildIdentity`, fingerprint validation and `SshPrivateKeyPem` where their existing contracts apply. Preserve the current resolved SSHJ0.41.2, aligned Bouncy Castle1.86 and SLF4J2.0.20 graph during the separate WebKit dependency review.

Initially admit **one controlling renderer and one terminal session**. A second Activity cannot steal ownership. Detach, recreation or renderer loss fences the attachment, requests interruption and keeps reconnect explicit. A process can die before persisting its terminal state; recover unfinished records as interrupted without replay. Hold the worker slot until cleanup and terminal persistence complete; quarantine uncertain helper cleanup. Use `closed` to mean transport termination, never arbitrary remote-command success. Keep eight attempts without eviction and record event truncation. Do not persist commands, output, clipboard contents or transcript hashes by default.

Freeze initial qualification limits at **10 seconds for renderer readiness or a pending output acknowledgment** and **15 minutes for an overall session watchdog**; retain bounded connection/authentication deadlines. Ordinary idle typing pauses must not trigger an acknowledgment deadline when no output is outstanding. These are test limits, not performance findings or a continuous-session service policy. Admission returns distinct accepted/full/stale/stopped outcomes; input and resize carry both current session and attachment identities. Drain the actual SSH stderr stream explicitly and cancel independently of blocked reads/writes.

Repository policy excludes downloaded third-party implementations from Git. Fetch and verify pinned core/fit archives into ignored cache/build output, reject unsafe archive paths/symlinks, and package only inspected allowlisted assets and applicable notices. Commit authored glue, exact integrity/provenance metadata and the reproducible asset preparation logic. Fail the build on missing/mismatched assets; no CDN fallback. Published bundles may avoid a new bundler after their actual contents are inspected. Preserve all existing Gradle verification digests and review every new resolved artifact. Correct the diagnostic's short close/hide explanation in the next APK to distinguish a cancellation request from process-loss recovery.
