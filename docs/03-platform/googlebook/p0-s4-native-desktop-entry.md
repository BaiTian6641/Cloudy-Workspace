## Entry decision

Carry forward the successful isolated **FreeRDP 3.32.2 arm64-v8a Android native/JNI build** and carry forward the real diagnostic adapter/packaging and device-load result; carry forward actual pin/NLA, first-failure diagnosis and changing-frame/explicit-cleanup evidence; next qualify controlled input/focus/cancel and sustained resource/performance behavior. Keep LibVNCClient as the VNC candidate, but **do not connect unpatched 0.9.15 to a server**: the [accepted source review](../../07-reference/2026-10-15-vnc-patched-source-selection.md) selects exact upstream `98aaee0560baa0332339b2ef464ea96ed9b9b28c`, containing the three identified fixes, with focused runtime regressions and Android build/integration still pending. The native build is a bounded result, not product adoption or protocol qualification.

Both eventual native engines belong to Desktop's own package/process, credentials and lifecycle. Ordinary RDP/VNC servers need no Cloudy agent or Console installation. A standalone upstream app can help identify an integration fault but cannot satisfy Cloudy's native client gate. No alternative protocol stack implementation is proposed.
