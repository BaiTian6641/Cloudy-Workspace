## Selected upstream method policy

At this pin, `SSHClient.authPassword(...)` supplies password plus keyboard-interactive fallback. Password-only policy must select `SSHClient.auth(username, method)` explicitly. Public-key, keyboard-interactive and other required workflows remain separate implementation work (R275).

`AuthPassword(finder)` also does not refuse password changes: its non-null default update provider returns null, but message60 handling builds a changed-password request. `Buffer.putSensitiveString(null)` encodes an empty string. A null constructor provider instead exposes a null dereference in `shouldRetry`. Those convenience-path findings follow selected source; the new strict path is separately exercised against a genuine encrypted server password-change challenge. [R276 AuthPassword](https://github.com/hierynomus/sshj/blob/6fad160fe36605a68847ac8a527750c615b4bd04/src/main/java/net/schmizz/sshj/userauth/method/AuthPassword.java), [R277 Buffer](https://github.com/hierynomus/sshj/blob/6fad160fe36605a68847ac8a527750c615b4bd04/src/main/java/net/schmizz/sshj/common/Buffer.java).

Keep a non-null provider, one-release finder and private typed refusal state; do not parse exception text or server prompts into policy. Strict compilation, unit cases and the real server challenge now establish this bounded refusal path; they do not qualify Android network authentication.
