## Exact defect and evidence boundary

The unchanged diagnostic **0.1.4/code5**, build reference `dc833678-46b0-47e3-bb4e-1a9cc804cbf5`, implements standard negotiated relative input. Its cursor presentation is incomplete:

- `RdpSession.pointer()` updates `frame.move(x, y)` for absolute input. `sendRelativeOnOwner()` submits relative input and increments counters without moving the rendered cursor.
- `RdpFrameBuffer.draw()` draws a custom cursor at its last stored position. `defaultPointer()` clears the bitmap; there is no software default-arrow path.
- The accepted native Android bridge's `android_Pointer_SetPosition()` returns TRUE without forwarding coordinates. Java handles cursor shape/default/hidden notifications but has no position callback. Shape handling exists; do not describe every cursor update as missing.

Inspect the [session](../../../qualification/probes/native-rdp/app/src/main/java/dev/cloudy/qualification/rdp/RdpSession.kt), [framebuffer](../../../qualification/probes/native-rdp/app/src/main/java/dev/cloudy/qualification/rdp/RdpFrameBuffer.kt) and [Java ABI](../../../qualification/probes/native-rdp/app/src/main/java/com/freerdp/freerdpcore/services/LibFreeRDP.java) against the accepted source identity before editing. The exact upstream [Android pointer callbacks](https://github.com/FreeRDP/FreeRDP/blob/97eff6ddfbbfaa8e42a126d362686bd001ff8bdc/client/Android/Studio/freeRDPCore/src/main/cpp/android_freerdp.c) and [pointer cache dispatch](https://github.com/FreeRDP/FreeRDP/blob/97eff6ddfbbfaa8e42a126d362686bd001ff8bdc/libfreerdp/cache/pointer.c) establish the position-callback entry point. Retain the reviewed patch chain; upstream source alone does not identify Cloudy's complete native build.

Android makes the system mouse pointer invisible while capture is active. A default cursor can therefore disappear, and a custom cursor can remain at the last absolute location even while relative events reach the host. This is a concrete client defect, not proof that it caused every reported movement failure. [Official Android capture contract](https://developer.android.com/develop/ui/views/touch-and-input/gestures/movement#pointer-capture), API26+.

The latest user exercise reports **captured movement fails and local release works**. The retained observation has **873 accepted relative JNI submissions** and **504 target mouse moves after capture confirmation**. The release edge is unknown, so those moves cannot be attributed specifically to the captured interval. Keep the counts, user observation and attribution limit together; neither a relative-delivery pass nor a total transport-failure conclusion follows. The earlier KRdp missing-relative-callback failure remains separate from this GRD/client-presentation question.

GRD50.2's [cursor renderer](https://github.com/GNOME/gnome-remote-desktop/blob/50.2/src/grd-rdp-cursor-renderer.c) emits cursor shape/default/hidden updates; no `PointerPosition` emission was found in that inspected file. An authoritative position bridge alone may therefore be insufficient for this exact server. Its [relative input callback](https://github.com/GNOME/gnome-remote-desktop/blob/50.2/src/grd-session-rdp.c) and [libei dispatch](https://github.com/GNOME/gnome-remote-desktop/blob/50.2/src/grd-session.c) are distinct from cursor presentation and still require actual delivery evidence.

## Bounded repair contract

1. **Authoritative position:** bridge the maintained `SetPosition(context, x, y)` callback to an instance-checked Java/session callback. Validate coordinate bounds against the current framebuffer, ignore retired instances, retain synchronous native callback ownership, and update cursor state under the existing drawing synchronization. Preserve callback failures through the established first-failure path.
2. **Cursor visibility and shape:** represent default-visible, custom-visible and server-hidden states separately. Draw a software default cursor when capture hides Android's pointer and the remote state requests a visible default. Preserve hotspot/shape bounds and clipping. Respect a server-hidden cursor, including applications intentionally hiding it for relative 3D operation; do not force an arrow into that state.
3. **Presentation-only prediction:** where position feedback is absent, explicitly distinguish a bounded predicted position from an authoritative server position. Seed from a known position or identify the initial estimate, accumulate only admitted relative motion, clamp presentation to the framebuffer, and reset/reconcile on authoritative updates, resize, connection and capture ownership changes. Do not claim agreement with server acceleration, pointer constraints, warps or application consumption. Keep prediction separate from delivery counters and qualification outcomes.
4. **Redraw ownership:** publish cursor changes through a coalesced UI redraw, not an unbounded main-thread task for every delta. Drawing and cursor replacement must obey the existing framebuffer lock/lifetime rules. Motion cannot retain stale native/GDI resources.
5. **Wire nonregression:** preserve the accepted signed-delta JNI/queue/core route and negotiated capability checks. Prediction must never emit absolute mouse movement, recentering or AINPUT as a fallback. Keep wheel/button release ordering and local capture release intact. A moving predicted cursor is UI feedback, not proof that the remote desktop moved.
