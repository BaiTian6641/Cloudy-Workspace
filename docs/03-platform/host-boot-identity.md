# Linux boot identity observation

**2026-10-16; HOST-LINUX-BOOT01 source and retained finite Linux runtime accepted after parent and independent review.** The internal `host/core/internal/bootidentity` Linux library adds `Read() (ID, error)` and immutable comparable `ID.String()`. It observes the boot UUID supplied by the caller's trusted procfs view. It is separate from [installation self-ID](host-installation-identity.md) and supplies no login/session identity, authentication or global container-independent host identity.

This is a bounded prerequisite of future capability/event correlation under [P4-S1](../05-delivery/phases/p4-host-integration.md). Existing event/capability schemas require boot identity, but this internal library is not wired to a service, CLI, pairing flow, capability response or event stream. Host executable 0.1.2, schemas and dependencies remain unchanged. P1-S4/P3-S1 prerequisites and P4 stage status remain unchanged.

## Operation and trust boundary

Every `Read` opens only `/proc/sys/kernel/random/boot_id` afresh. It reads at most 38 bytes and accepts exactly 36 lowercase UUID characters with version 4/RFC variant and trailing LF. It rejects whitespace variants, uppercase, truncation, extra bytes and malformed records. The returned ID owns an immutable canonical string; its zero value is invalid and prints as empty. The library never generates, substitutes, persists or caches an ID.

The opened reader is closed exactly once before publishing success. Open/read/close failures return a zero ID and fixed stage-specific error; underlying OS and secondary cleanup causes remain private without `Unwrap`. A read or close error cannot become a valid observation. Tests inject failure paths without changing global filesystem hooks.

The caller must trust the procfs mount view. The byte limit bounds allocation and consumed data, not the duration of I/O on a malicious replacement mount. No mount authenticity, cross-container uniqueness, reboot transition, session correlation or remote authentication is qualified. No identifier appears in test output.

## Primary API/source and checks

This inspected upstream version differs from the actual running kernel and is not a statement that this workstation runs v6.18. Process-group cleanup and notification are insufficient.
