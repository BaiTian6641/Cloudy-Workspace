# SSH fixture signal-test review

**Date:** 2026-10-15. **Scope:** host test synchronization and CI diagnostics. The production SSH fixture and the Android 0.6.0 application are unchanged. The [actual device run](../../qualification/results/P0-S3/2026-10-15-ssh-pty-probe.md) remains bound to its original source, APK and preserved fixture bytes.

The initial source passed 41 local repository tests, while [hosted repository CI](https://github.com/BaiTian6641/Cloudy-Workspace/actions/runs/38724229346) failed the regression step. Public log downloads required authentication, so a reviewed workflow change retained the same unittest discovery and exit policy while exposing up to ten escaped failure annotations, each with at most 8,000 traceback characters. Test-specific diagnostics disclose only bounded fixed audit fields, without raw records or private paths.

The [first detailed diagnostic](https://github.com/BaiTian6641/Cloudy-Workspace/actions/runs/38725272238) showed exit 74 instead of 129 in the combined hangup/SIGHUP test. An initial reading incorrectly attributed its line to the master-close branch; the [subsequent diagnostic](https://github.com/BaiTian6641/Cloudy-Workspace/actions/runs/38725818061) isolated the explicit SIGHUP branch. The [final diagnostic](https://github.com/BaiTian6641/Cloudy-Workspace/actions/runs/38726108375) reported exit 74 and a final `ready-written` audit event without a terminal event. The earlier descriptor-restoration hypothesis was not established and was discarded.

The fixture writes readiness bytes before syncing its corresponding audit event. The test could receive those bytes and immediately send SIGHUP while that audit was still in progress. Its signal handler raises an exception; an interrupted audit deliberately marks durability uncertain and prevents any later completion record. Expecting a clean signal outcome at that moment was an invalid test ordering assumption.

A deterministic regression now injects SIGHUP from the fourth `fsync` in the test launcher, while a real PTY fixture writes its readiness audit. It requires actual exit 74, the bounded audit-I/O failure diagnostic, and the absence of a final event. It reproduces the hosted signature while retaining the fixture's conservative evidence policy.

The separate clean-signal case now waits for a test-only pipe token emitted immediately before the first real input read, after the readiness audit has returned. Only then does the parent send SIGHUP. It still requires exit 129 and the distinct `signal-hup` audit reason; the master-close case still requires `terminal-hangup`. There is no added sleep, ignored failure or production protocol change. The pipe, PTY and child process have bounded waits and cleanup.

Independent review accepted the synchronization, descriptor ownership, bounded cleanup and retained failure semantics. All 20 fixture tests passed on Python 3.12.14, 3.13.12 and 3.14; the clean-signal and interrupted-audit cases each passed 20 repetitions on Python 3.12.14. The complete local repository suite passed all 42 tests, together with Python 3.10 grammar AST compilation, pinned Ruff, repository/schema checks and JavaScript syntax. Android source, dependencies, permissions, package hash and its 134 JVM tests/16 suites are unaffected. Hosted verification for the final commit is recorded in [execution state](../05-delivery/execution-state.md); local success alone does not establish that result.
