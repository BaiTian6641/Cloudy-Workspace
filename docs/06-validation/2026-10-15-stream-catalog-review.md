## Authored source review

[CatalogController.java](../../qualification/probes/native-stream/android/app/src/main/java/dev/cloudy/qualification/stream/CatalogController.java) implements the existing controlled NvHTTP interface. It invokes the actual upstream `getAppListRaw()` and quiet parser, without calling PairingManager, native media or playback. Every request must be GET HTTPS `/applist` on the exact immutable numeric address and HTTPS port. Positive explicit HTTPS ports prevent upstream's zero-port HTTP discovery route. The pinned leaf is checked even for CA-valid presented chains; redirects and automatic connection retries are disabled. The actual Call is registered before execute and remains cancellable until response/body closure. The entire read is clipped to the original credential deadline and a 1 MiB body limit. Exceptions expose only fixed sanitized outcomes, not raw messages, URLs or peer content.

[CatalogPeerProfile.java](../../qualification/probes/native-stream/android/app/src/main/java/dev/cloudy/qualification/stream/CatalogPeerProfile.java) reads only the bounded eight-field private public-trust profile, with no application ID. It requires schema 1, exact keys, numeric nonloopback unicast IPv4, distinct valid ports, exact 64-hex pin and canonical Base64 for one exact DER certificate. It freezes the peer independently of mutable file contents. Selecting an actual returned ID constructs the existing frozen PlaybackProfile; no placeholder ID is used for validation.

[CatalogPolicy.java](../../qualification/probes/native-stream/android/app/src/main/java/dev/cloudy/qualification/stream/CatalogPolicy.java) rejects nonpositive/duplicate IDs and more than 128 entries. Titles are bounded and stripped of control/format characters for native UI display; they are not commands or journal text. Catalog entries, titles and selection remain in process memory. Empty catalogs remain empty. The Activity captures catalog generation when creating selection controls, and the model requires that generation and current membership. Each new read clears the old peer/list/selection before admission; a failed or stale response cannot leave an old ID launchable. Preview requires the selected immutable profile and a separate fresh authorization, without a manual-profile fallback.

[StreamProbeViewModel.java](../../qualification/probes/native-stream/android/app/src/main/java/dev/cloudy/qualification/stream/StreamProbeViewModel.java) adds CATALOG under the same process lease as identity, pairing, reconciliation and playback. READY identity, local-network permission, actual DEVICE_CREDENTIAL type 1 and the same live store attempt are required. Qualification, provider acquisition and run stay in one worker action using the original callback's maximum 30-second window. The controller is published before a final ownership/cancellation check. Operator cancel, real backgrounding, deadline and owner clearing cancel both the identity attempt and real HTTP call; no retired provider is reused. Catalog does not consume/reset the native one-run guard.

The shared [NetworkEvidenceStore.java](../../qualification/probes/native-stream/android/app/src/main/java/dev/cloudy/qualification/stream/NetworkEvidenceStore.java) scans pairing, playback and catalog directories before any of those network actions. A durable pending reservation precedes network work. Malformed, unfinished or evidence-unavailable records block every lane; exact-byte reconciliation includes catalog paths/operations and never acknowledges a current-process record. Original records remain unchanged, host state remains UNKNOWN, and reconciliation performs no replay or remote cleanup. Catalog terminal write/readback gates release, including onCleared. Evidence failure retains ownership or blocks subsequent network admission rather than inventing successful closure. Journals contain actual typed stages/counters, not titles, lists, XML, peers, certificate bodies, keys or PINs. PLAY records only the selected application ID and catalog generation for this binding.
