## Reviewed implementation

[StreamProbeActivity.java](../../qualification/probes/native-stream/android/app/src/main/java/dev/cloudy/qualification/stream/StreamProbeActivity.java) adds an explicit Pair button, masked native PIN field and explicit local-network permission request. The PIN field accepts at most four characters, disables saved state/autofill/IME learning and is cleared after submission or real backgrounding. `FLAG_SECURE` protects the diagnostic window. The model separately validates exactly four ASCII digits and wipes rejected or retired owned arrays. Upstream's immutable in-memory PIN `String` remains a documented erasure limitation; no PIN is persisted or logged.

[PairingProfile.java](../../qualification/probes/native-stream/android/app/src/main/java/dev/cloudy/qualification/stream/PairingProfile.java) reads only `no_backup/pairing-config.json`, bounded to 32 KiB. Schema 1 requires exactly `profileId`, `numericAddress`, `httpPort`, `httpsPort`, `certificateSha256` and `certificateDerBase64` alongside `schema`. The initial fixture accepts exactly **127.0.0.1**, distinct valid ports, a 64-hex SHA-256 pin and canonical Base64 for one exact DER public certificate of at most 16 KiB. It rejects extra fields, alternate loopback spellings, DNS and general LAN addresses. The frozen adapter additionally checks certificate validity and pin equality. The parent controls the actual ADB reverse route and loopback-only cleartext network policy.

[StreamProbeViewModel.java](../../qualification/probes/native-stream/android/app/src/main/java/dev/cloudy/qualification/stream/StreamProbeViewModel.java) rejects missing API 37 `ACCESS_LOCAL_NETWORK` before creating an attempt, displaying authentication or opening a network operation. It checks permission again before qualification and through the controller's per-operation guard. Pair requires an already `READY` identity and creates a fresh store attempt with `DEVICE_CREDENTIAL`. Actual success type 1 is mandatory. Qualification, obtaining `store.provider` and running `PairingController` occur in one worker action using the same live attempt and original credential callback timestamp. The 30-second authorization window includes qualification and all network calls. No enrollment completion, identity generation/deletion, software-key fallback, automatic retry or host unpair is introduced.

The [process lease](../../qualification/probes/native-stream/android/app/src/main/java/dev/cloudy/qualification/stream/StreamOperationLease.java) serializes identity and pairing operations across models. The owner publishes the live controller, then checks cancellation/current ownership again before running it. Operator cancel, real backgrounding, authorization deadline and owner clearing revoke the store attempt and cancel the actual controller. Configuration recreation reattaches the existing AndroidX callback without another authenticate call. Focus loss alone remains distinct from backgrounding because the system prompt can take focus. Busy ownership is retained until the worker and outstanding prompt retire.

The separate atomic `no_backup/pairing-journal` has a 16-attempt limit. Existing identity and native-load directories are not migrated or rewritten. A newly reserved or authorization-waiting record is unclosed. Prior malformed, unfinished or evidence-unavailable pairing records block admission; evidence publication failure blocks new network work in the process. Terminal evidence records controller stage/failure stage, actual pairing completion, final client-TLS read and application-list byte count separately. It excludes PINs, endpoints, URLs, peer bodies and host certificate material, and does not assign a false zero host-connection count. A completed pairing record is not rewritten for a main-queue cancellation arriving after its work retired. Cancellation is never interpreted as proof that host enrollment was absent or revoked.
