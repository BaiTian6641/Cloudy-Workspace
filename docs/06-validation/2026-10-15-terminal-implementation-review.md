## Implemented source and ownership

The new `TerminalConfig`, `TerminalState`, `TerminalJournal`/codec, `TerminalRuntime` and `TerminalActivity` form a separate lane. The existing finite SSH/SFTP/exec/PTY configuration, operations and journal remain separate. The finite engine's edits extract its existing algorithm policy and bounded private-key reader into `SshConnectionPolicy` and `SshKeyFile`; they do not replace its fixed protocol with an interactive operation or supply fabricated sentinel fields.

`TerminalTransport` uses the pinned SSHJ 0.41.2 `SSHClient.startSession`, `Session.allocatePTY`, `Session.startShell`, channel streams and `Session.Shell.changeWindowDimensions` APIs. It requests `xterm-256color`, the renderer's measured initial cell dimensions, zero pixel dimensions and an empty terminal-mode override map, retaining server defaults. It does not inherit the finite fixture's forced echo/newline settings or send a fixed command/marker exchange. These public library contracts and the request implementation are recorded in R93–R96/R98 in the [source register](../07-reference/source-register.md).

Native code owns endpoint configuration, expected and accepted host identity, private-key loading, authentication, SSH sockets, operation admission and durable history. The page receives only opaque session/attachment identities and terminal frames. Unknown trust closes before authentication and before reading the private key. Native enrollment persists trust, then a separate explicit Connect is required. Every host-key verification, including rekey, checks the configured endpoint and exact expected/accepted fingerprint. The first observed fingerprint stays immutable; a post-authentication rekey rejection is a failed authenticated attempt, not a new pre-authentication trust prompt.

The shared policy retains ECDH P-256, ECDSA P-256 host signatures, AES-128-GCM and no compression. `hmac-sha2-256` is the retained MAC proposal; GCM provides the actual authenticated-encryption tag rather than a separate packet MAC. The implementation retains `DefaultSecurityProviderConfig` and compares provider names/order without modifying Android's global provider list. The prior [SSH dependency adoption review](2026-10-15-ssh-dependency-adoption.md) remains applicable to SSHJ 0.41.2, aligned Bouncy Castle 1.86 and SLF4J 2.0.20. This narrow diagnostic algorithm policy is not a broad server-compatibility claim.

One process-owned runtime admits one controlling terminal/renderer. Session and attachment UUIDs fence delayed input and resize messages. The native screen provides permission, Connect, trust, Disconnect, details, refresh and explicit recreation controls. It does not reconnect automatically. Loss of the visible owner, recreation, renderer failure, permission loss or explicit stop closes admission and requests independent socket cancellation. Process recovery records an unfinished session as interrupted without replaying input or opening another connection. This visible-owner policy does not establish an Android background-service classification; the [operation-lifetime boundary](../03-platform/googlebook/p0-s2-operation-lifetimes.md) still applies.

## Bounded byte flow and result semantics

| Boundary | Implemented limit or behavior |
| --- | --- |
| Input | A fixed 64 KiB ring, including the currently in-flight writer chunk. Each offered byte array is accepted in full or refused. Bytes are copied; binary and UTF-8 boundaries are not decoded by native transport. |
| Input dispatch | One writer, with admission armed before the native `open` observation and I/O released only after that callback returns successfully. No thread or executor task is created per keystroke. |
| Resize | One coalesced pending size, bounded to 2–512 columns and 1–256 rows. Resize and input share a writer with alternating opportunity when both remain pending. |
| Output | Independent stdout/stderr consumption with callbacks of at most 16 KiB. Concurrent callbacks feed the renderer's synchronized bounded flow. |
| Renderer credit | At most 256 KiB outstanding output, a 64 KiB low-water mark and 64 queued/posted frames. Credit returns only for the exact next sequence and byte count after the xterm parser callback. |
| UI delivery | One coalesced native drain runnable, at most four output frames per UI turn. Renderer input also bounds unacknowledged input bytes to 64 KiB and outstanding input requests to 128. |
| Deadlines | Ten seconds for readiness, queued output delivery or pending parser acknowledgment; 15 minutes for the separately owned session watchdog. Connection/authentication/request waits retain bounded ten-second settings. Quiet terminal reads have no idle protocol timeout. |
| Cleanup | Cancellation closes the tracked socket and wakes queue waits. Owned writer/reader/library-cleanup threads share a finite ten-second join budget. Failed or uncertain cleanup returns `cleanupCertain=false`; runtime keeps new admission unavailable. |
| Journal | Separate schema-1 history, eight attempts without eviction, 96 retained events per attempt with counted overflow, and a 128 KiB file cap. AtomicFile writes require bounded exact readback before successful persistence is reported. |

`inputBytes` counts submissions whose local write and flush returned; it is not a remote acknowledgment. `stdoutBytes` and `stderrBytes` count bytes read, not bytes rendered. `ptyInitialCols/Rows` describe the requested allocation and `ptyLastCols/Rows` the last submitted window-change request. SSHJ does not request a resize acknowledgment; actual remote dimensions must be measured during device/backend qualification. The journal records bounded phase metadata, algorithms, identities and counters, plus the actual renderer provider/version and listener/binary feature flags sampled before admission. It stores no command text, output, clipboard contents or transcript hashes.

The ordinary Shell interface has no public exit-status getter. `closed` describes termination and is not an arbitrary remote-command success verdict. A nominal remote EOF must be followed by channel closure and certain native cleanup. Before reporting final closure, the runtime waits for outstanding output to reach the renderer's parser callbacks. Parser completion establishes neither pixel presentation nor latency. Explicit Disconnect and process-loss recovery remain distinct from a clean remote EOF.

The configuration and shared key file are each capped at 16 KiB and reject special files/symlinks. The key reader admits the existing unencrypted SEC1 EC PEM envelope; SSHJ performs actual decoding/authentication. Its public content API retains a String, so complete secret zeroization is not claimed. AtomicFile readback similarly does not claim power-loss durability. Official AtomicFile behavior is tracked as G50.

## Renderer security, input and platform guards

`TerminalWebViewBridge` loads an allowlisted set of packaged assets from `https://appassets.androidplatform.net/assets/terminal/`. It registers `WebViewCompat.addWebMessageListener` for that exact origin before loading. Every incoming message must be an ArrayBuffer from the main frame and match the expected origin, protocol version, session/attachment identity, next sequence, operation and length. Unknown paths receive an explicit denial instead of a network fallback. Navigation, new windows, downloads, file/content access, mixed content, remote resources and browser permission requests are blocked. The page has no generic RPC, credential access, `addJavascriptInterface`, remote-script evaluation or video/SFTP bridge.

The native boundary uses official WebKit APIs: `WebViewAssetLoader` (G107), origin-scoped messaging and its UI-thread/main-frame callback (G108/G111), binary `WebMessageCompat` and reply APIs (G109/G110), plus renderer-process loss handling (G112). Listener support and `WEB_MESSAGE_ARRAY_BUFFER` are checked against the actual installed WebView provider before a connection begins; unsupported capability produces an explicit unavailable result. The selected library is `androidx.webkit:webkit:1.17.1` (G106/G113). The reviewed public APIs and library minimums are mapped in the [increment handoff](../03-platform/googlebook/p0-s3-terminal-renderer-increment.md#local-asset-and-native-boundary); the APK's minSdk 35 covers the API26 renderer-loss callback. Compilation and actual provider support still require their own evidence.

The authored page passes output to `terminal.write(Uint8Array, callback)` and acknowledges only the actual parser callback, preserving split UTF-8 bytes across ordinary output chunks. `onData` text is encoded once as UTF-8; `onBinary` converts byte-valued characters directly. It does not also forward `onKey` or synthesize native keystrokes. A whole oversized/full input action is refused visibly and is not automatically retried. Terminal-generated replies share this bounded path and must not be counted as physical typing. R103–R105 document the upstream API, encoding and flow contracts.

Cloudy terminal/ANSI tokens are retained, font size incorporates the system scale once, and fit uses measured cells rather than window pixel guesses. `screenReaderMode` is enabled. Remote clipboard OSC 52 and hyperlink OSC 8 are consumed locally; terminal links are disabled in this diagnostic surface. Native trust/host presentation cannot be replaced by remote title text. Core/fit use the upstream default Unicode6 width behavior; Unicode11/grapheme addons are not adopted. R106/R107/R111/R112 establish source/browser context, not Googlebook IME, modern grapheme or TalkBack qualification.

The application retains native Android permission handling. API37 `ACCESS_LOCAL_NETWORK` is checked before admission, at phase/output/control boundaries and by a periodic active-session admission check; denial does not start a connection. Permission grant does not connect automatically. The behavior and VPN/enforcement limits remain those documented by G79–G81 and the prior platform investigations. This source change adds no terminal foreground service, service type or background-work exemption.

## Review findings resolved

The transport author reviewed the renderer lane; the renderer author independently reviewed the transport/configuration/shared extraction and test source. The parent owns the integrated runtime, journal, UI, dependency graph and final validation. The accepted source corrections are:

- **Outbound sequence versus concurrent closure:** sequence allocation is committed only for an actual native post. A worker closing the bridge between queue claim and delivery cannot leave a skipped sequence before CLOSED.
- **Late acknowledgment/delivery:** credit claiming and acknowledgment enforce expiry under the same flow lock before changing queue state. A late callback cannot erase an already-expired deadline before the periodic timer runs. A fake-clock regression exercises both late ACK and late delivery.
- **Late readiness:** the first READY message checks elapsed time before setting its proxy/ready state or calling native admission. An expired readiness callback cannot establish a connection by arriving before a delayed timer callback.
- **Native cleanup precedence:** failed or unjoined helpers retain explicit uncertainty even when cancellation, callback failure or rekey races with shutdown. Input dispatch is released only after successful durable `open` publication. The input capacity includes bytes held by a blocked writer, preventing dequeue from silently creating extra allowance.

- **Displayed trust consent:** the native dialog carries an immutable session/attachment/configuration/endpoint/fingerprint ticket. The IO owner rechecks it against the current unknown-key row and independent reference before persistence. Nine policy tests reject stale dialogs and changed/already-enrolled identities.
- **Cleanup evidence:** failed cleanup and expired cleanup remain distinct durable reasons; both retain the unavailable worker slot.
- **Lint guards:** optional WebKit calls carry explicit feature checks at each call site. The exact 1.17.1 lint artifact incorrectly diagnoses Kotlin base constructors even with the real renderer-loss override. Only the private client factory suppresses `MissingOnRenderProcessGone`; [G116/upstream fix](https://github.com/androidx/androidx/commit/8003b908c7bfaecd6636512ad5cb1720a142ad51) explains the defect. Its `lint.jar` SHA-256 is `a18c55d2c853585a209edb5ccb641daa3c7176cc544a3b147e78c6d73650b1ed`. The real handler invalidates, removes/destroys and returns true under [G115/official guidance](https://developer.android.com/develop/ui/views/layout/webapps/handle-termination). Recheck and remove this exception on a corrected dependency update.

No remaining actionable finding was reported in the two independently reviewed source lanes. The parent separately reviewed all delegated source/assets and the integration, with no remaining actionable source finding. This does not certify WebView interoperability or physical input. The source test additions comprise 26 transport/configuration/shared-policy tests, 15 renderer frame/flow JVM tests and nine authored JavaScript helper/glue tests at this review point. Tests use the real pure helpers and bounded real-thread waits; fake DOM/xterm objects are confined to Node test instrumentation and are not renderer implementations or device evidence. Exact executed totals belong in the validation record below.

## Private configuration and operator usage

The selected app/user's private `files` directory owns three independent terminal files. Do not overwrite, migrate or import the finite probe's `ssh-config.json`, `ssh-client-key` or `ssh-journal.json`. Do not commit any real endpoint configuration, key, private journal or terminal transcript.

| File | Exact role |
| --- | --- |
| `terminal-config.json` | Strict flat schema 1 endpoint settings, UTF-8, regular file, at most 16 KiB. Exactly the five fields below; no sentinel, remote-directory, password or generic command field. |
| `terminal-client-key` | Separately provisioned unencrypted SEC1 EC PEM private key within the shared bounded format. Keep private and owner-controlled; unsupported/encrypted formats are refused. |
| `terminal-journal.json` | Runtime-owned trust and bounded attempt history. Do not create invented process/build/revision metadata, edit active history or delete it to obtain another test slot. |

| Configuration field | Accepted value |
| --- | --- |
| `schemaVersion` | JSON integer `1`. |
| `host` | Canonical literal IPv4: four decimal octets, no padded octets, first octet 1–223, each octet at most 255. DNS names and IPv6 are outside this initial qualification increment. |
| `port` | JSON integer 1–65535, including ordinary SSH port **22**. A temporary fixture's high port is an operator choice. |
| `username` | ASCII login matching `[a-z_][a-z0-9_-]{0,31}`. |
| `expectedHostKeySha256` | Independently verified OpenSSH-style SHA-256 fingerprint: `SHA256:` plus canonical unpadded Base64 of 32 bytes. Obtain it from the actual server's public host key through a trusted route. It is not automatically enrolled trust. |

Duplicate, unknown, missing, mistyped or relaxed-JSON fields fail closed. `endpointId` derives from host/port; `configIdentity` also includes login/reference fingerprint and a terminal-specific domain. These are derived runtime identities, not additional configuration fields. Terminal trust is held separately even when a finite SSH fixture used the same endpoint.

1. The designated device owner preserves existing APK/journal evidence, verifies the exact candidate package and selected Android user, then provisions the two real private configuration/key files through the reviewed debug workflow. No device is altered by this document.
2. Open the native terminal diagnostic from the baseline screen. Grant local-network permission through its native control if required. Refresh loads configuration; permission or refresh alone does not connect.
3. Press Connect. Renderer readiness and supported binary APIs precede native session admission. For an otherwise matching unknown host key, the first attempt stops at `trust-required` before authentication. Inspect the native expected/observed identity and explicitly accept trust; successful enrollment still does not connect.
4. Press Connect again to authenticate and open the ordinary PTY. Input, resize and whole-paste refusal now operate through the bounded terminal route. The details dialog shows native history/provider information rather than a raw transcript.
5. Use Disconnect explicitly. Closing/hiding/recreating the owning Activity or losing its renderer interrupts the session according to the initial visible-owner policy. Reconnection requires a new explicit action. At eight attempts, preserve evidence and use a separately reviewed maintenance procedure; this increment supplies no automatic eviction or journal rotation.

A separate reviewed ordinary-shell backend is required for useful qualification. The historical forced-SFTP and fixed exec/PTY dispatchers do not become interactive shell servers because this UI exists. A forced shell in a private working directory is not a security sandbox; its process still has the fixture account's authority. Fixture startup, real commands, cleanup and original-data preservation remain parent-owned operations with separate evidence.

## Remaining qualification gates

Before any terminal capability decision, bind results to the exact APK/source, Googlebook build and actual WebView provider/version/features. Exercise a real ordinary shell, measured remote PTY resize, an actual available alternate-screen TUI, terminal queries, sustained output/backpressure, prompt cancellation, whole-paste refusal and fragmented UTF-8/binary delivery. Verify the expected cleanup independently of displayed cancellation state, including renderer loss, last-visible-owner loss and process recovery without replay.

Physical keyboard/trackpad/mouse, Ctrl/Alt/Escape/Tab behavior, focus release, selection, native CJK IME preedit/commit/cancel and candidate placement still require actual device/input evidence. ADB-injected characters cannot qualify those physical/IME cases. Test 130% and 200% font scaling, narrow desktop tiles, wide/combining/CJK/emoji cases, and actual Android screen-reader navigation/announcements. Enabled `screenReaderMode`, screenshots and a plausible accessibility tree are not a TalkBack pass.

Also test rejected origins/subframes/stale identities, malformed/oversized envelopes, blocked resource/navigation attempts, clipboard/link escapes, renderer readiness/ACK failure and journal persistence failure. These remain bounded experiments rather than an exhaustive production security certification. Ordinary SSH independence from the custom host agent, integrated SFTP/drop, X11 windows, persistent background sessions and the full Console product remain separate requirements. No gate is relaxed by this source review.
