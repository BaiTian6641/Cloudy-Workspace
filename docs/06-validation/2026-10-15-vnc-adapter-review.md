Unmodified upstream could not satisfy strict policy. `SetClientAuthSchemes` filters outer RFB3.7/3.8 types but not the server-selected RFB3.3 route, and its VeNCrypt subtype selector independently admits anonymous/None/plain variants. Its OpenSSL verification accepts `preverify_ok` before checking the configured fingerprint and lets a fingerprint match override other verification failures. The narrow [adapter-owned patch](../../qualification/probes/native-vnc/adapter/security-and-cancel.patch) applies configured outer policy on 3.3, adds a borrowed per-client subtype allowlist, and invokes a bounded unconditional actual peer-leaf DER callback after TLS succeeds and before credential exchange. Only VeNCrypt X509Plain is permitted. TLS1.2 minimum/no renegotiation protect the once-per-handshake pin decision. Normal upstream TLS/crypto/decoders remain in use; this is not a replacement TLS or RFB implementation.

The authored policy uses complete DER parsing, nondeprecated OpenSSL ASN.1 time comparisons and constant-time SHA256 pin comparison. Expired/not-yet-valid or malformed certificates cannot be accepted merely by pin equality; CA-validity does not bypass a different configured pin. This is intentional leaf-pin trust, not CA/name validation. Configuration immutably binds profile ID, numeric transport address, port and pin to memory-only credentials. The callback must succeed before X509Plain username/password bytes are returned. Session password storage and upstream temporary credential copies are wiped; JVM-wide erasure is not claimed. Fixed numeric status replaces upstream peer-controlled log strings. Existing source/license notices are preserved, and source archives, patched source/static archive, matching headers and captured build inputs remain private.

The worker alone owns connect, initialize, TLS writes, decode and cleanup. One monotonic non-pointer handle is registered at a time; acquired JNI calls prevent free. Callback globals survive through actual join. Socket publication/cancel shutdown/cleanup unpublication use the same mutex, avoiding shutdown of a recycled descriptor. Initial numeric TCP connect has a three-second bound before publication; no unbounded libc DNS API is exposed. I/O retries and TLS handshake/write loops consult cancellation/deadline, and plain-write select is bounded. These are cooperative boundaries: a nonreturning Java callback or decoder CPU work cannot safely be killed. Sink callbacks must return promptly, join must run off callback/main threads, and a false join retains the owner. Free rejects active/unjoined ownership explicitly.

Input admission is bounded to 256 typed events, with real upstream send results reported separately from admission and host receipt. Pending unsent events complete false before terminal notification. Planned release queues tracked buttons before keys; immediate cancellation cannot promise remote release. Positive dimensions are bounded by 4096 per axis and 8,388,608 pixels. Each frame callback receives an independent Java-owned RGBA copy; native decode/scratch and resize overlap are separate allocations. The per-frame 32MiB bound is not total RSS. The future UI must coalesce/retain bounded copies. No clipboard, drives/USB, desktop agent, vault or relative emulation is exposed.
