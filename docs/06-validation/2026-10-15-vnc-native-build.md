JPEG is included rather than defining a lossless-only baseline. Official stable libjpeg-turbo 3.2.0's 2,537,858-byte release archive is pinned to publisher asset digest `6f30092cef9fb839779646608f4ee14ae3cbac989c47fa05e841b0841f09878e`. Its supported Android CMake build produces a PIC static library with ARM64 SIMD; the client links it directly. OpenSSL 4.0.1 reuses the exact accepted FreeRDP Android API29 shared output, successful receipt and matching generated/public headers, verified before copying into an isolated stage. This does not share credentials or a daemon. The complete OpenSSL source archive is retained; no byte-reproducible regeneration claim is made for the imported debug-bearing binaries. Android system `libz.so` remains OS-owned; pinned NDK stubs/headers are build provenance, not device implementation identity. Bundled miniLZO uses supported `LZO_CFG_NO_UNALIGNED=1`, with no source patch or sanitizer suppression. PNG is disabled.

NDK 29.0.14206865/Clang 21, SDK CMake 4.1.2 and its Ninja compile real client TLS/crypto/JPEG paths for `arm64-v8a`, Android29 and `RelWithDebInfo`. No upstream patch is applied. The helper asserts the actual compile graph and generated features, rejects `tls_none.c`, then parses actual ELF and dependency closure. Its accepted `entry-03` library is 3,797,968 bytes, SHA256 `ab5b7d38ab507dd6058be52356c9a7ac2bd4353ec7e5b3a54a030e0ecf4544d4`. It depends on the two imported SSL/crypto libraries and Android libc/libdl/libm/libz. All three shared objects have 16384-byte minimum load alignment and expected SONAMEs, without RPATH/RUNPATH. This is static ELF inspection, not APK zip alignment or a successful Android loader invocation.

Archive byte counts/hashes are checked before extraction or cache reuse. Extraction rejects traversal/absolute paths, wrong roots, duplicate members, links, special files and overwrite. Ordered patch declarations must match actual patch files. Authored/helper inputs are captured before compilation and compared before publication; source trees are also checked after compilation. Each new run uses isolated source/build directories, four-job compilation, a 240-second per-step bound and 8MiB log cap with shared process-group cleanup on errors/timeouts/interruption. Offline verification reconstructs the exact VNC/JPEG source, validates the OpenSSL import and source archive, verifies all prepared/evidence hashes and checks ELF without requiring network, SDK or compilation. A changed locked helper/input invalidates the retained receipt.

Actual entry-03 completed 118 JPEG and 11 VNC steps. It retains 13 upstream OpenSSL deprecated-API warnings, without suppression, and no errors. This normal native build does not execute ASan/UBSan or establish runtime algorithm/provider availability.
