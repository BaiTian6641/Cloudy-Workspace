# VNC timing and controlled marker source/build review

**2026-10-15.** Reviewed increment: VNC Android 0.1.3/code4, build reference `478b0a46-2d02-4eeb-940b-e25e602f8aa1`, plus the controlled canvas-03 host target. This review covers authored diagnostic behavior and actual compilation/package checks. It does not establish runtime success or identify the earlier startup/keyboard cause.

`VncDiagnostics` allocates a new object when an operation is accepted, before worker enqueue. Atomic compare-and-set records only the first observation; no worker reset erases a callback that already arrived. All milestones use the same Android elapsed-realtime clock: accepted action, worker entry, native-start invocation, CONNECTED callback, first valid frame callback, first successful bitmap conversion, first unique Canvas draw, stop request and successful join. Unobserved values serialize as JSON null. Do not subtract host-wall-clock events from these values. Native-start time precedes its boolean result; CONNECTED follows full initialization and is not an authentication-only event. Draw means the actual Canvas API call, not measured visibility. Main-thread drawing can race a terminal journal checkpoint, so null means unobserved at that checkpoint, not proof that presentation could never occur later.

The sink captures the per-attempt diagnostics identity, then retains existing native-handle checks. Old native callbacks cannot be admitted merely because a freed native address is reused. Existing join-before-free/admission remains unchanged. Main-thread bitmap work and UI observation do not reset timestamps, begin new sessions or replay actions. No new native ABI or authentication-success callback was added. The native security dispatcher evidence remains R244/R245 as explained in the [prior idle-budget result](../../qualification/results/P0-S4/2026-10-15-vnc-auth-idle-build.md); no new security conclusion is inferred from a startup phase label.

F8-only frame-view counters distinguish down/up observations, rejection by focus/window/connection/Meta gates, unowned key-up and owner-queue acceptance/rejection. Counters saturate at 4,000 and record no arbitrary key text. Owned key-up still retires through the existing path before ordinary gates. These counters cannot observe hardware events consumed before reaching the frame view. A successful owner enqueue is not native admission, a socket write or host acknowledgement. The journal explicitly states per-key write confirmation is unavailable. This deliberately avoids a sequence-registration race: native completion can arrive before a JNI send call returns its sequence. Existing aggregate native write counters remain separately identified.

The no-frame presentation now shows the actual observed phase rather than an undifferentiated blank/error. Existing native fields, focus gates and release policy are preserved. Focus is observed, not forced. The Qt host canvas logs focus-in/out and activation/deactivation events and state snapshots, including marker-time focus snapshots; those observations do not assume that focus caused the earlier missing marker. Public contracts are [QWidget focus policy](https://doc.qt.io/qt-6/qwidget.html#focusPolicy-prop), [QWindow screen assignment](https://doc.qt.io/qt-6/qwindow.html#setScreen), [fullscreen](https://doc.qt.io/qt-6/qwindow.html#showFullScreen) and [QScreen name](https://doc.qt.io/qt-6/qscreen.html#name-prop).
