The production owner executor serializes native operations, but automatic cleanup has two entry routes. An already running `pollNative()` can observe `stop` and call `cleanup()` directly. Concurrent `stop()` also enqueues cleanup. If the first attempt publishes `CLEANUP_UNCERTAIN`, the queued task calls cleanup again without an explicit retry decision. Repeated `stop()` can additionally overwrite uncertainty with `STOP_REQUESTED`. The public contract permits retry only through deliberate `retryCleanup()` after uncertainty; the inspected source does not enforce that contract in this interleaving. This is a source finding, not a measured device failure or a claim that a particular historical JVM case exercised it.
