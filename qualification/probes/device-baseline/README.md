# Device baseline and window qualification probe

This is a dedicated **P0 diagnostic Android APK**, not Cloudy Console or Cloudy Desktop. Version **0.4.1** includes a separate real HTTPS/Android user-initiated transfer experiment and permits the scheduler-assigned VPN route when it advertises Wi-Fi/Ethernet. It does not select an underlying network to bypass the VPN. **Refresh diagnostics** still re-reads shared build/input/video-decoder reports, captures the requesting window and samples its engagement counters. Installing, compiling or running this probe does not establish remote-protocol, USB, physical-input, decoder-performance or desktop-product support, and this increment does not complete P0-S2. The baseline report retains schema 3; transfer state uses its own private journal. Both reports derive the installed source version from generated BuildConfig metadata.

The [transfer contract](../../../docs/03-platform/googlebook/p0-s2-transfer-probe-contract.md) defines the finite generated fixture, scoped CA trust, assigned LAN network, explicit user start, cancellation and recovery cases. The manifest now declares network, UIDT, LAN and notification permissions only for that experiment; it has no foreground service. Missing private configuration or denied permission is an unavailable operation, never a generated success result. Exact build/review and physical evidence must be recorded separately before claiming any case passed.

## Build and check

The pinned candidate uses AGP **9.4.0**, its built-in Kotlin compiler, Gradle **9.6.0**, SDK **37.0**, Build Tools **36.0.0**, min SDK **35**, target SDK **37**, JDK **21** to run Gradle, and Java/Kotlin **17** bytecode. The qualification-only engagement dependency is **androidx.window:window:1.6.0-alpha05**, with explicit **androidx.core:core:1.8.0** for its public `androidx.core.util.Consumer` callback type. Window publishes Core at runtime scope; the direct declaration makes the type available when compiling this probe. The resolved graph is pinned and checksum-verified; see [the toolchain record](../../../docs/03-platform/googlebook/probe-toolchain.md) and [packaged dependency notices](THIRD_PARTY_NOTICES.md). There is no Compose, NDK, dependency-injection or network library. JUnit **4.13.2** is test-only. These settings are not build or device evidence, and this alpha experiment does not select the product dependency stack.

From this directory, with the project-local tool paths supplied by the maintainer:

```bash
export ANDROID_HOME="$(git rev-parse --show-toplevel)/.cache/android-sdk"
export ANDROID_SDK_HOME="$(git rev-parse --show-toplevel)/.cache/android-user"
export ANDROID_USER_HOME="$ANDROID_SDK_HOME/.android"
export GRADLE_USER_HOME="$(git rev-parse --show-toplevel)/.cache/gradle-home"
mkdir -p "$ANDROID_SDK_HOME" "$ANDROID_USER_HOME" "$GRADLE_USER_HOME"
./gradlew --version
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Select the intended JDK 21 in the invoking environment. The wrapper/tool distributions are maintained separately from the probe sources. The legacy Android SDK home and Android user home deliberately resolve to the same `.android` location. Kotlin compilation runs in process to avoid an additional user-home daemon cache; it uses the same pinned compiler. Compilation includes Kotlin warnings as errors; Android Lint treats warnings as errors. Do not add blanket suppressions to obtain a passing result.

Focused JVM tests cover independent marker state, supplied-field restoration and invalid-state reset, counter overflow, generation replacement, late-callback rejection, task-identity collisions, live-window capacity, closed-record eviction, event correlation/retention and observation deduplication. Engagement tests run the production lifecycle controller against test-only queues/backends: stop before queued registration, accepted-but-delayed old delivery, late old callbacks after restart, two independent windows, partial registration failure, failed cleanup, bounded queued lifecycle work, admission rejection, pending versus reported modes, repeated callbacks and history overflow. Ledger tests reject obsolete epochs/generations and accept historical cleanup without reviving closed windows. These tests do not execute AndroidX/framework callbacks, task launches, the native UI, file persistence or physical-device behavior.

The `AndroidGradlePluginVersion` exception is limited to `gradle/wrapper/gradle-wrapper.properties`: Gradle 9.6.0 is intentionally pinned to AGP 9.4's documented baseline. One declaration-local `GradleDependency` exception covers the explicit Core 1.8.0 pin matching this Window candidate's audited runtime graph. See [toolchain rationale](../../../docs/03-platform/googlebook/probe-toolchain.md). Other dependency notices and all source/resource warnings remain checked.

## Install, run and retrieve

Use the authorized target's serial privately in `CLOUDY_DEVICE_SERIAL`; do not paste it into source-controlled records. The maintainer must select the device explicitly. These commands are instructions, not a claim that they have run:

```bash
adb -s "$CLOUDY_DEVICE_SERIAL" install -r app/build/outputs/apk/debug/app-debug.apk
adb -s "$CLOUDY_DEVICE_SERIAL" shell am start -W \
  -n dev.cloudy.qualification.baseline/.BaselineActivity
```

Wait for **Private report saved**. The UI shows reported values and explicit pending/error state; codec detail lives in the private report. **New window**, **Change marker**, **Recreate this window** and **Refresh diagnostics** have stable resource IDs (`new_window`, `change_marker`, `recreate_window`, `refresh_diagnostics`) for explicit target-scoped UI inspection. Inspect current UI bounds before using automation; do not assume old coordinates still identify the same control.

For the first two-window experiment:

1. Record window A's logical ID, observed task ID, fresh Activity generation ID, marker and counter. Change its marker twice.
2. Press **New window** in A. The explicit same-package Intent requests a distinct document task with `FLAG_ACTIVITY_NEW_DOCUMENT | FLAG_ACTIVITY_MULTIPLE_TASK`. Confirm a second actual task and visible native window B. A successful `startActivity` return is only a launch-request observation. The OS chooses placement; manually arrange windows when necessary.
3. Confirm B starts with a different logical ID, marker A and counter zero. Change B once, return to A, and verify A retains its own marker/counter. Compare the two `windows[]` records in the exported JSON.
4. Press **Recreate this window** in A. Verify the same logical ID and marker/counter, a different generation ID, `restored-bundle`, and the actually observed task ID. Do not treat the task ID as a permanent identity. B's state must remain unchanged.
5. Resize/move each native window, change focus, minimize/restore and inspect correlated lifecycle/geometry events. Preserve native caption controls. Repeat on a narrow desktop tile and at a larger font scale: the entire probe scrolls, including all controls. Viewport bounds, not the changing diagnostics text height, trigger geometry observation.

These steps are test instructions, not recorded passes. Physical task/window isolation, framework state restoration and window interaction require actual evidence. Process death, foreground-service timeouts, operations surviving recreation, IME/physical input, additional displays and VM integration remain separate experiments. See the [P0-S2 window contract](../../../docs/03-platform/googlebook/p0-s2-window-probe-contract.md).

Export to an ignored private location from the repository root:

```bash
mkdir -p qualification/results/private
adb -s "$CLOUDY_DEVICE_SERIAL" exec-out run-as dev.cloudy.qualification.baseline \
  cat files/baseline.json > qualification/results/private/device-baseline.json
python3 -m json.tool qualification/results/private/device-baseline.json > /dev/null
```

`run-as` requires the installed debuggable build and its package identity. Treat failure as a failure; do not substitute sample JSON. Read `schemaVersion`, `revision`, `collectionInProgress`, section statuses, `retention` and `lastCollectionAtDeviceUtc` before using an export. A previous file can remain after a save failure; the UI reports that limit. Sanitize and review an export before deriving public evidence, recording the exact APK SHA-256, source commit, build/backend identity, observation time and limitations. Device clock timestamps are reported clock readings, not synchronized measurement evidence.

Schema **3** preserves schema 2's bounded `windows[]`, identities, local state, geometry and correlated lifecycle events, and adds `windows[].engagement` plus process-level `engagementCleanup`. Each engagement snapshot identifies a subscription epoch within the enclosing Activity generation. Its bounded event history and callbacks carry actual device UTC and elapsed-realtime clock readings. Consumers must check schema/status/epoch explicitly; `baseline.json` remains the file name. Schema 1's single `window` object was replaced in schema 2.

## Engagement observation experiment

The implementation calls `WindowInfoTracker.getOrCreate(activity)`, then registers `WindowEngagementInfo` with the **same tracker instance and same AndroidX Consumer** retained for removal. It copies actual `engagementModes` names, including unknown future names within explicit bounds. It does not instantiate library values, copy the library's device heuristic, inject successful results, change density or force a preferred mode. See the [reviewed engagement contract](../../../docs/03-platform/googlebook/p0-s2-engagement-probe-contract.md) for exact source/version/availability and acceptance cases E01–E05.

1. Launch a window and inspect `thisWindow.engagement` in the UI or its corresponding private JSON record. `pending` with `modes: null` means no callback has yet been received for that epoch. A real callback containing `TOUCH` is `reported`; an actually reported empty set is also distinguishable from null. A registration return alone is not a mode observation.
2. Open a second window and compare logical/task/generation identities and per-window engagement histories. A subscription starts on each actual `onStart`; stopping one window must not stop the process-owned dispatch thread or the other window's subscription.
3. Minimize/restore and recreate a window. `onStop` invalidates its epoch immediately; a subsequent `onStart` gets a fresh epoch even when the Activity generation is unchanged. Recreation gets a new generation as before. Old callbacks cannot become the current mode of a restarted or replacement Activity.
4. Record the API's actual values, failures and omission counters. An initial `TOUCH` followed by `PRECISE_POINTER` is preserved as two mode observations. Equal repeated values increment counters without generating repeated history entries, UI deliveries or writes; **Refresh diagnostics**, the next mode change or lifecycle transition publishes the sampled totals. Late rejected callbacks follow the same sampling policy, so a retired controller can receive further rejected callbacks after its last saved checkpoint without another write.
5. Verify the report is saved, export privately and bind evidence to the exact APK/source. Inspect real callback and cleanup behavior on the device separately from JVM test results. These instructions are not recorded passes.

All registration/removal and library executor jobs use a single persistent process-owned `HandlerThread` with a prepared Looper. Library calls never run under recorder/controller locks, and callbacks only copy modes and update bounded observation state. They do not reenter registration/removal. One pending main-thread delivery per controller reads its **latest** epoch/status when delivered; a queued epoch-1 result cannot overwrite epoch 2. The recorder also coalesces UI delivery. Every job supplied by AndroidX to its Executor runs normally; the probe does not claim to bound AndroidX, platform or Looper queues.

The probe permits at most **eight** outstanding engagement reservations across the process. It reserves before queuing registration, so a blocked backend cannot accumulate unbounded registration/removal requests during rapid start/stop. At most one registration job and one cleanup job are queued per reservation. Untracked windows create no backend; admission rejection is explicit and never evicts another window. After temporary capacity rejection, a new lifecycle start can try again; Refresh does not silently create a new subscription.

Removal is attempted once with the original tracker/Consumer, including after a partial registration failure. `RuntimeException`, an unimplemented interface's `NotImplementedError`, and runtime `LinkageError` are reported by class without exception messages or fabricated fallback modes. Failed cleanup is recorded separately as `cleanup-failed`, keeps its admission slot reserved for the process lifetime and contributes to the UI's partial/error result. A later no-op removal cannot prove cleanup: the alpha implementation can remove its adapter-map entry before backend cleanup throws. A bounded process-level failure record survives replacement of the original Activity generation. The app clears its own Activity references after registration/stop; failed library cleanup may still retain backend resources or an Activity until process death. There is no claimed hard timeout on a blocking library/framework call.

## Observations and limits

### Finite transfer experiment

Prepare the private Linux fixture using [the host helper](../../../tools/README.md#temporary-https-transfer-fixture). Import only its `android-config.json` into the debuggable app's `files/transfer-config.json`, preserving private command/export logs and verifying byte-for-byte readback. Never import the server or CA private key, add a system certificate, disable hostname verification, or grant unrelated permissions. Configuration reload occurs through **Refresh transfer state** while no attempt is active.

From a baseline window, **Open transfer experiment** launches the nonexported native screen. **Request local network access** invokes the actual runtime37 permission prompt; **Request progress notifications** is a separate optional notification request. Neither grant starts a transfer. Press **Download test fixture** while visible. The app uses a real UIDT `JobService`, the assigned Wi-Fi/Ethernet network, and its scoped HTTPS factory. **Cancel transfer** stops that exact attempt; a notification action must not affect a later attempt. **Recreate transfer window** changes the visible Activity UUID while the process/attempt identities remain independently observable.

The separate `files/transfer-journal.json` schema1 records up to eight attempts and their bounded transition histories. Payloads remain at `files/transfer-payloads/<attempt UUID>.part`, including failed/canceled partials and verified completed content. There is no remote publication or rename. The runtime refuses further starts at the attempt limit; it never silently evicts evidence. Preserve the journal and payloads before any deliberate operator reset. A new process reconciles unfinished attempts to interrupted and rechecks saved completed files; no work resumes automatically.

Network I/O, file copying/hashing and journal writes run outside the Activity/main thread. The probe uses ten-second connection/read timeouts and a ten-minute cooperative transfer deadline; a framework call must return before a cooperative check can run. Progress records describe bytes written, not a separate per-chunk power-loss guarantee. Completion requires file sync/close, an independent reread of exact length/SHA-256, and a journal write/readback. Android process loss, disk faults and actual durability still require the recorded physical cases; a successful API return does not prove those broader properties.

The framework-Views screen keeps every control in its native scroll view and respects system/caption insets. Diagnostic prose and internal state labels are not the product design system. No new UI/network/test library is introduced by this experiment.

| Surface | Collected facts | Limits |
| --- | --- | --- |
| Build | Manufacturer/model/product/device/hardware, OS build ID/display/fingerprint, release/API/security patch/incremental and supported ABI list | The fingerprint identifies an OS build; no serial, Android ID, account, network identity or hardware unique identifier is requested |
| Input | Reported source masks/classes, keyboard type, virtual/external flags | No names, IDs, descriptors, vendor/product IDs, pressed keys or text; Refresh obtains a new snapshot, not a live behavioral test |
| Video decoders | `ALL_CODECS` video MIME entries, canonical/alias names, vendor/hardware/software reports, supported/required low-latency/secure/tunneled features, profile levels and video ranges | Includes special-mode/secure codecs and aliases. No decoder instance, actual frame decoding, stream compatibility, concurrency, thermal, throughput or latency test |
| Window/display | Current/maximum metrics, density, native system/caption/IME insets, caption rectangles and inset frame, current physical display mode and reported refresh rate | Caption rectangles use the inset frame's coordinate space and can differ from final layout. Empty rectangles/hidden captions are actual observations, not an assumed API failure |
| Window identity/state | Random logical window ID restored only from that Activity's Bundle; observed `taskId`; random fresh generation ID on every `onCreate`; marker/counter, restoration outcome | Random probe identities are not hardware identifiers. An observed task ID is opaque and is not used as a permanent identity. The recorder never supplies restoration state |
| Lifecycle | Creation/start/resume/pause/stop/destroy, top-resumed state, save-instance-state, focus, multi-window and configuration callbacks; changed window snapshot events, all correlated with a window generation | Last 128 events for this process only. Android need not call destruction callbacks before process death; a queued write can be lost |
| Engagement | Actual alpha05 mode names, device UTC/elapsed times, epoch, registration/cleanup state, callback/repeat/rejection counts and bounded per-generation history | Hints do not establish physical input correctness or preferred density. Null pending differs from a reported empty set or TOUCH. Equal repeats and rejected late callbacks are sampled rather than continually saved; stopped/closed records are historical |

The recorder lives for the application process, so Activity recreation retains its bounded event ring. It serializes codec queries and file writes on one worker, coalesces refresh/save work, and uses `AtomicFile` for `files/baseline.json`. Because `AtomicFile` can log commit errors without throwing them, a bounded readback must match the expected bytes before the UI reports that revision as saved. A failed write can leave the previous file; a readback failure leaves the current file unverified. This is not a guarantee against arbitrary power loss. No activity or credential is shared with another application.

Each Activity owns immutable local marker/counter state and explicitly saves four small fields into its own Bundle. A new document receives no identity/state Intent extras and starts fresh. A valid Bundle restores the logical ID and local state; an invalid version, UUID, marker or negative counter resets the entire diagnostic state and reports `invalid-bundle-reset`. The counter saturates rather than wrapping. A new Activity always receives a new generation ID. Configuration recreation remains enabled; the manifest does not consume configuration changes to keep an Activity artificially alive.

The recorder retains at most **eight** logical-window records. A stopped or unfocused Activity still occupies a live slot. A new generation in the same task replaces that logical window's previous generation and clears its old geometry; late callbacks cannot close or overwrite the replacement. A duplicate logical ID in a different live task is rejected with `live-task-identity-conflict`. When full, the oldest retained closed record may be evicted; if every record is live, registration is rejected with `registry-capacity`. Counters report evictions, rejected registrations/callbacks and superseded generations. **New window** is disabled for an untracked window or when all tracking slots are occupied. System UI/external launches can exceed this diagnostic limit; they display untracked state and record the rejection, without pretending to be captured. This bounds evidence memory, not Android's task count or the number of windows the OS permits. Closed records remain historical observations and do not imply their tasks are still present.

Limits are explicit: at most 64 input entries, 128 video decoder entries, eight video MIME types per decoder, 16 profile/level pairs per type, 32 caption rectangles, and a 256 KiB codec-record budget. There are at most eight retained geometry snapshots of 32 KiB each and 128 shared correlated events. Engagement adds at most 32 transition/history entries per retained generation, 16 mode names per observation, 80 characters per name, and eight process cleanup-failure records. Histories drop their oldest entries with explicit counters; name/count omissions are reported. An oversized geometry snapshot becomes an explicit collector error. The full saved report remains limited to 512 KiB; combined maximum sections need not fit, and exceeding the total reports a save error and keeps the previous file. Vendor codec enumeration can block in framework code, so it runs off the UI thread; the probe does not claim a hard timeout on that framework call.

The baseline collector performs local diagnostic reads and needs no permission. Version 0.4.0 adds INTERNET, ACCESS_NETWORK_STATE, ACCESS_LOCAL_NETWORK, RUN_USER_INITIATED_JOBS and POST_NOTIFICATIONS for the explicit transfer experiment, with a nonexported transfer Activity/cancellation receiver and a nonexported JobService protected by BIND_JOB_SERVICE. Backup remains disabled and probe files are excluded from backup/device-transfer rules. No external file provider or USB access is registered. The exported launcher ignores external payloads; opening the transfer screen does not schedule a download.

## Official reference and test review

Reviewed 2026-10-15:

- [MediaCodecList](https://developer.android.com/reference/android/media/MediaCodecList): `ALL_CODECS`, `getCodecInfos`; inspect actual installed reports rather than a model-name inference.
- [MediaCodecInfo](https://developer.android.com/reference/android/media/MediaCodecInfo) and [CodecCapabilities](https://developer.android.com/reference/android/media/MediaCodecInfo.CodecCapabilities): supported types/profile levels, canonical name/alias and reported flags; hardware acceleration flags are manufacturer reports, not independent measurements.
- [InputManager](https://developer.android.com/reference/android/hardware/input/InputManager) and [InputDevice](https://developer.android.com/reference/android/view/InputDevice): input enumeration, source classes and keyboard/virtual/external flags.
- [WindowMetrics](https://developer.android.com/reference/android/view/WindowMetrics), [WindowInsets](https://developer.android.com/reference/android/view/WindowInsets), and [desktop windowing](https://developer.android.com/develop/adaptive-apps/guides/support-desktop-windowing): visual-context bounds/density and API-35 inset frame/caption bounding rectangles. The minimum SDK deliberately covers these methods.
- [Activity](https://developer.android.com/reference/android/app/Activity): lifecycle, focus, configuration and multi-window callbacks; lifecycle observation is distinct from a survival guarantee.
- [Intent](https://developer.android.com/reference/android/content/Intent), [document tasks](https://developer.android.com/guide/components/activities/recents), and [Activity manifest](https://developer.android.com/guide/topics/manifest/activity-element): standard launch mode with explicit new-document/multiple-task flags. `FLAG_ACTIVITY_LAUNCH_ADJACENT` is intentionally absent because its split-screen contract is not desktop placement evidence. No `maxRecents` value is used as an assumed live-task cap.
- [WindowManager](https://developer.android.com/reference/android/view/WindowManager): activity-scoped `PROPERTY_SUPPORTS_MULTI_INSTANCE_SYSTEM_UI` (API 35) exposes a system affordance; it does not implement task isolation or force placement. Minimum SDK 35 covers this and the previously used inset APIs.
- [WindowInfoTracker](https://developer.android.com/reference/androidx/window/layout/WindowInfoTracker), [WindowEngagementInfo](https://developer.android.com/reference/androidx/window/layout/WindowEngagementInfo) and [Window 1.6.0-alpha05 release](https://developer.android.com/jetpack/androidx/releases/window#1.6.0-alpha05): actual register/remove callback surface and mode reports. The [engagement contract](../../../docs/03-platform/googlebook/p0-s2-engagement-probe-contract.md) records the inspected canonical source artifact, exact checksum and alpha lifecycle constraints; this is qualification-only dependency usage.
- [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile) and [app-specific storage](https://developer.android.com/training/data-storage/app-specific): private bounded snapshot persistence; one worker owns writes because AtomicFile is not a locking primitive.
- [Build](https://developer.android.com/reference/android/os/Build): reported build properties, without querying serial/unique IDs.
- [Built-in Kotlin](https://developer.android.com/build/migrate-to-built-in-kotlin) and [CompileSdkSpec](https://developer.android.com/reference/tools/gradle-api/9.4/com/android/build/api/dsl/CompileSdkSpec): no separate Kotlin Android plugin; explicit API-37 minor level 0.

The repository reference-research workflow and installed official testing-setup skill were read with the project's recorded overrides. This small probe uses platform Views plus focused JUnit tests; no Hilt, Compose screenshot framework, phone tests, alpha toolchain migration or synthetic successful device implementation was introduced. The explicitly scoped alpha Window library supplies the real engagement API. Physical window/focus, engagement, refresh, export and failure behavior remain separate checks for the maintainer and independent reviewer.
