# Finite controlled native playback engine

This is a real engine/control increment against Moonlight Android v12.2, revision `b48494cb96bff23d8886c4775cc4f39a1075495d`. It composes **after** the accepted [pairing overlay](../pairing/README.md). It invokes actual upstream `NvConnection`, `MediaCodecDecoderRenderer`, `AndroidAudioRenderer` and the accepted native core. No Activity control, new authorization, host launch, Surface creation, Android build, device stream or performance result has been executed by this increment. The existing diagnostic UI is unchanged. This is not a replacement protocol, decoder or audio implementation.

The [lock](sources.lock.json) binds the required pairing patch, this [playback patch](finite-playback.patch), each exact before/after upstream file and the new authored Java/test inputs. `NvHTTP.java`'s before hash is the output of the frozen pairing overlay; the other two before hashes are the exact retained upstream files. Apply pairing first, then playback. The parent-owned Android preparer verifies this dependency and replays the overlays. The accepted native library and receipt are unchanged; no native rebuild is needed for these Java changes.

## Parent API and ownership

Create `PlaybackProfile(profileId, numericIpv4, httpPort, httpsPort, rtspPort, appId, publicServerCertificate, sha256LeafPin)`. It freezes public certificate bytes and the pin, checks certificate validity, requires an explicit numeric unicast IPv4 address outside loopback, distinct valid ports and a positive selected app ID. IPv6 is unsupported in this first preview. Selecting/proving the actual LAN route remains parent-owned; accepting a profile is not connectivity evidence. The existing loopback-only pairing profile is not relaxed. Preserve the existing stable client/profile ID so the already paired identity is selected deliberately.

The fixed stream request is **1280×720, H.264 SDR, 60 fps, 10,000 Kbit/s, stereo audio, no controllers**, with explicit local transport and packet size 1392. It uses an initialized upstream `NvApp` with the supplied real app ID, so no app-name lookup occurs. A conflicting running app is rejected; it is never automatically quit/replaced. Actual decoder setup rejects a different format/geometry or rate above 60 rather than silently presenting an unqualified configuration.

`STREAM_CFG_LOCAL` is a fixed invariant of this profile: it skips upstream `NvConnection.detectServerConnectionType()`. Its four existing `ACCESS_NETWORK_STATE` Lint baseline entries therefore remain inactive. Enabling `STREAM_CFG_AUTO` later requires the actual network-state permission and retiring those affected entries. The selected decoder/helper/audio paths do not call that detector, `NetHelper`, `Game` or `ControllerHandler`; the corresponding inactive baseline paths are not activated by this controller. The metered-data argument is unused for the forced H.264 choice and is not a claim about the device's network.

After a fresh genuine `DEVICE_CREDENTIAL` success type 1, qualify the same existing key and obtain its provider on the same live identity attempt. Then construct:

```java
new PlaybackController(profile, qualifiedProvider, ownerGuard,
        originalAuthenticatedAtElapsedMillis, durationMillis);
```

Duration must be positive and at most **30,000 ms**, measured from the original callback, including time already spent qualifying the key. No callback time is resampled or saved authorization restored. The parent guard must cheaply reject backgrounding, stale identity attempts, cancellation and permission loss; provider getters retain the existing unlocked/authentication guards. The controller also checks API 37 local-network permission. The entire first preview stops when its authorization/deadline is unavailable. No longer product-session lifetime, software key, authentication retry or policy extension is implied.

Call `Result run(Activity, Surface)` on a dedicated non-UI worker. It is blocking and single-use. The Activity is required by the actual upstream renderer; do not replace it with a fake Context. The parent must hold its existing process-wide operation lease across identity qualification, this run and incomplete cleanup. `processActive()` exposes playback ownership; `requiresFreshProcess()` exposes the one-run limit below. Pairing/identity UI admission must integrate that lease before activation.

The parent owns the actual Surface. Prefer a `TextureView` and its real `SurfaceTexture`: construct a `Surface` when available, call `surfaceLost()` when destroyed, return `false` from `onSurfaceTextureDestroyed`, and retain both objects until `retired()` is true before releasing them. Android explicitly assigns release responsibility to the client for that [TextureView ownership choice](https://developer.android.com/reference/android/view/TextureView.SurfaceTextureListener). Stop on real backgrounding, configuration/Surface loss and permission loss; do not reattach a fresh Activity to the old renderer. No Java RGBA framebuffer or software-rendering substitute is introduced.

`cancel()` and `surfaceLost()` revoke the HTTP lease and interrupt native connection work without waiting on startup, decoder monitors or joins. They do not prove retirement. `run()` performs cleanup off UI; `snapshot()` returns immutable bounded diagnostic state. If cleanup throws or remains blocked, retain ownership and the Surface. After a returned `CLEANUP_PENDING` result, `retryCleanupBlocking()` may be called on a non-UI worker. A concurrent external retry while `run()` remains active only requests cancellation and returns false. No timeout is relabeled as successful native/codec cleanup.

## Exact controlled changes

`NvConnection.cloudyStartBlocking(...)` tracks starter retirement with a latch, acquires the existing global native permit through deadline-checked waits, and releases only an acquired permit exactly once. It uses the controlled `NvHTTP` constructor and a new explicit pinned-HTTPS server-information method. Requests are limited to exact HTTPS `/serverinfo`, `/launch` and `/resume` at the immutable peer/port. Redirects, automatic connection retries, app lookup, host `/cancel`, unpair and HTTP fallback are unavailable in this route. Bounded numeric version strings avoid passing arbitrary peer strings into native version-error diagnostics. Returned RTSP/RTSPENC URLs must match the selected numeric peer and RTSP port without userinfo, query, fragment or non-root path.

Actual OkHttp calls remain registered through response-body read and close. Bodies are capped at 1 MiB; call/read time uses the remaining original deadline, with connect/write additionally capped at five seconds. A 50 ms watchdog checks the owner/provider/deadline and cancels the real call/native attempt. Native media still uses upstream RTSP, UDP video/audio and ENet control. TCP-only ADB reverse is not a sufficient media route, and pinned HTTPS does not mean the media channels themselves use TLS.

### Native cancellation race and process limit

The exact retained common-C `src/Connection.c` resets `ConnectionInterrupted=false` during `LiStartConnection`, then invokes the first `stageStarting` callback before platform/network stages. A cancellation just before native entry can therefore be overwritten by that reset. This adapter stores cancellation outside the core, reasserts the native interrupt from each native stage-start callback and repeats it through the watchdog. The checks before/after HTTP and before entering native code prevent ordinary late-start admission. `cloudyStopBlocking()` waits for the starter to retire, then serializes actual native stop/bridge cleanup; incomplete work retains ownership. This is cooperative cancellation, not forced preemption of arbitrary codec/native work.

The retained core also creates/detaches its `AsyncTerm` termination callback thread (`Connection.c`, `terminationCallbackThreadFunc` / `ClInternalConnectionTerminated`) without an exported join operation. The Java bridge listener is process-global. Immediate reuse could let an old asynchronous callback reach a newly installed listener. For this **first preview**, the authored process lease therefore permits only **one playback run per process**, including failed preparation. There is no reset API; a second run is explicitly `UNAVAILABLE`, even after real retirement. The parent must stop/reopen the process before another playback attempt. This bounded qualification restriction avoids a speculative native rewrite; repeated product sessions remain a separate ownership question. Pairing and native metadata loading are not themselves playback lifetimes.

### Real decoder, Surface and evidence

The renderer adds `cloudySetRenderTarget(Surface)` without taking release ownership. It still uses actual upstream MediaCodec selection, low-latency configuration and buffer submission. A real one-pixel EGL context queries `GL_RENDERER`, restores/cleans its resources and leaves an existing current context untouched. Failure returns an empty **unknown** metadata value; no GPU name is fabricated. `MediaCodecHelper` receives that actual/unknown metadata. AVC availability and real codec setup must succeed; no codec-name assumption substitutes for setup.

Evidence separates **decode-unit submissions** (which can be several units per frame), **output buffers released for rendering** (excluding drops), and actual **MediaCodec frame-rendered callbacks**. The latter uses the public listener independently of upstream's disabled render-time statistic. It records only atomic counts, not pixels or an unbounded UI post per frame. Callbacks can be delayed/batched or be absent after the codec leaves execution; [Android's listener contract](https://developer.android.com/reference/android/media/MediaCodec.OnFrameRenderedListener) does not turn them into photon or end-to-end latency measurements. Final counters are observations before actual retirement, not a guarantee every queued callback was delivered.

`Result` exposes typed phase/failure/stop reason, actual native return/termination codes (`Integer.MIN_VALUE` means native start was not called), startup and cleanup truth, negotiated setup geometry/format, bounded actual codec name, manufacturer-reported hardware flag, GL-metadata availability, and distinct HTTP/video/stage counters. The [hardware flag](https://developer.android.com/reference/android/media/MediaCodecInfo#isHardwareAccelerated()) is device-reported metadata, not proof of speed. Final immutable metrics are cached, then Activity/decoder/connection references are cleared. The controlled decoder stop joins its threads before marking completion, preserves interruption, and makes actual codec cleanup safe for partial setup and repeated native/owner cleanup. The unselected upstream connection path remains separate.

The real upstream audio renderer creates/plays an AudioTrack and participates in native cleanup. Audio effects are disabled. Controller/haptics and HDR are not negotiated; unexpected HDR fails the preview. No mouse, keyboard, native IME or relative-pointer UI is integrated here. Those must later use the actual upstream input APIs with Cloudy's focus/capture/release policy and cannot be inferred from video startup.
