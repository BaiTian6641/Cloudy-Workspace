# Android LibVNCClient native build entry

This entry builds the actual pinned client library for **arm64-v8a / Android API29**, with OpenSSL TLS, zlib, bundled miniLZO and Tight JPEG enabled. There is no app, JNI adapter or simulated session. It carries forward the [accepted source selection](../../../docs/07-reference/2026-10-15-vnc-patched-source-selection.md) and [27 portable host regressions](../../results/P0-S4/2026-10-15-vnc-regressions.md); it does not repeat those tests or qualify the same paths on Android.

The exact inputs are in [sources.lock.json](sources.lock.json). LibVNCClient is commit `98aaee0560baa0332339b2ef464ea96ed9b9b28c` (its CMake version label remains 0.9.15). Official libjpeg-turbo **3.2.0**, published 2026-06-30, is acquired from the publisher's release archive with its exact asset digest and compiled as a PIC static library with Android ARM64 SIMD. It is linked into `libvncclient.so`; TurboJPEG/Java tools are not built. PNG is disabled. System zlib is the Android OS-owned `libz.so`, linked through the pinned NDK API29 stub and headers; their build hashes do not identify a device's zlib implementation.

OpenSSL **4.0.1** reuses the exact accepted RDP Android shared build. Both libraries, the accepted receipt and all imported generated/public headers are pinned by byte count/hash. Import copies into a new private stage, verifies library hashes against the successful receipt, and never mutates or rebuilds the original prefix. This avoids a second TLS implementation or an unnecessary OpenSSL rebuild. Library reuse does not share app credentials or a daemon. Legacy provider/plugin discovery and actual authentication methods remain future adapter concerns; no provider is silently added to this native closure.

Prerequisites: existing Android SDK with stable NDK **29.0.14206865**, SDK CMake **4.1.2** and its Ninja, plus the exact accepted OpenSSL prefix/receipt described above. The helper installs nothing. From the repository root, choose a fresh run name and supply the retained OpenSSL prefix containing `include/openssl` and regular `lib/libssl.so`, `lib/libcrypto.so` files:

```sh
python3 tools/prepare_vnc_native.py --build --run entry-03 \
  --openssl-prefix /path/to/accepted/arm64-v8a-prefix \
  --openssl-receipt .cache/native-rdp/cursor-native-receipt.json
python3 tools/prepare_vnc_native.py --check --run entry-03
python3 -m unittest discover -s tests -p test_prepare_vnc_native.py -v
```

`--sdk` may select another SDK root with the locked versions. The helper verifies cached archives before reuse or downloads exact HTTPS bytes into `.cache/native-vnc/downloads/`. It rejects unsafe archive roots/paths, duplicate files, links and special files. Each build gets a fresh run and temporary source/build stage; no old build/cache graph is reused. Compiler steps use at most four jobs, 240 seconds per step and an 8 MiB log limit, with process-group cleanup on failure/timeout/interruption. It snapshots authored inputs before compilation, rejects source/input changes before publication, and preserves step logs and failure records. The first failed run predates the added authored snapshot; its specific failure and compiler logs are retained, without claiming a complete failed-run source snapshot.

The actual CMake graph must include `tls_openssl.c`, `crypto_openssl.c`, `rfbclient.c` and bundled miniLZO, reject `tls_none.c`, and define the selected SSL/zlib/JPEG features. The helper checks actual AArch64 shared ELF, SONAME, 16KiB `PT_LOAD` alignment and dynamic closure, rather than treating `WITH_OPENSSL=ON` as proof that TLS was found. This alignment check is not APK zip alignment or Android loader/runtime evidence. Compilation retains upstream diagnostics; deprecated OpenSSL APIs are not hidden or treated as modern authentication qualification.

Output lives in `.cache/native-vnc/<run>/prepared/`: three actual libraries under `nativeLibraries/arm64-v8a/` and source/notices/imported headers/receipt under `nativeNotices/`. The successful receipt binds authored inputs, actual tools/zlib stub/header hashes, both source trees, native files, all prepared notice bytes and compiler evidence. Offline `--check` requires no SDK, download, native compilation or execution: it reconstructs source from retained exact archives/patches, checks the OpenSSL import and every prepared/evidence hash, and parses ELF. A changed tool/lock/patch makes the receipt stale. Source caches, downloaded implementation and raw logs remain ignored/private.

Actual **entry-03** completed JPEG's 118 steps and VNC's 11 steps, then passed offline preparation verification. `libvncclient.so` is 3,797,968 bytes, SHA256 `ab5b7d38ab507dd6058be52356c9a7ac2bd4353ec7e5b3a54a030e0ecf4544d4`; it needs `libssl.so`, `libcrypto.so`, `libz.so`, `libc.so`, `libdl.so` and `libm.so`. The two imported OpenSSL libraries retain their accepted RDP hashes. All three ELF files have 16384-byte minimum load alignment and matching unversioned Android SONAMEs. The VNC compile reports 13 upstream OpenSSL deprecation warnings and no errors. Earlier entry-01 completed JPEG then failed on a helper header-path assumption (`src/` in 3.2.0); entry-02 found all dependencies but the helper rejected harmless doubled whitespace in a generated macro. Both failed runs are retained; neither is called a native pass. Entry-03 corrects these helper assumptions without upstream source edits.

The prepared notice set includes full pinned LibVNC/JPEG/OpenSSL archives, GPLv2/miniLZO source terms, libjpeg-turbo `LICENSE.md`/`README.ijg`, OpenSSL Apache2.0 text, the actual static JPEG archive, and captured authored/shared build inputs. Full source archives retain additional file-specific notices. The OpenSSL build provenance is the accepted RDP receipt and source archive, not a byte-reproducibility claim. Its upstream configuration was `Configure android-arm64 shared no-tests no-apps no-docs -U__ANDROID_API__ -D__ANDROID_API__=29 --prefix=<private-prefix> --libdir=lib`, with the accepted bounded four-job recipe. Recreating it with different build paths may produce different debug-bearing bytes and requires a newly reviewed import pin. The [open-source Desktop decision](../../../docs/adr/0010-desktop-open-source-distribution.md) does not itself approve this exact distribution closure; source/build/license review remains required before shipping.

Official guidance inspected: [pinned LibVNC CMake](https://raw.githubusercontent.com/LibVNC/libvncserver/98aaee0560baa0332339b2ef464ea96ed9b9b28c/CMakeLists.txt), [libjpeg-turbo 3.2.0 Android/CMake instructions](https://raw.githubusercontent.com/libjpeg-turbo/libjpeg-turbo/3.2.0/BUILDING.md), [official 3.2.0 release](https://github.com/libjpeg-turbo/libjpeg-turbo/releases/tag/3.2.0), and [CMake 4.1 FindOpenSSL](https://cmake.org/cmake/help/v4.1/module/FindOpenSSL.html), checked 2026-10-15. The web tool could not open the GitHub release API, so Python's HTTPS client read the official API metadata, including the tarball's SHA256 digest.
