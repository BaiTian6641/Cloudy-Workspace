# Bounded LibVNCClient JNI adapter entry

**2026-10-15:** real Android native/Java compilation succeeds; no app, Android loading or server connection has been executed. The parent remains integration leader. This authored ABI embeds a narrowly patched PIC LibVNCClient archive and the accepted PIC JPEG archive in `libcloudy-vnc-jni.so`. It loads only that JNI library and the accepted `libssl.so`/`libcrypto.so`; **do not load or substitute the original `libvncclient.so`**. The extended `rfbClient` struct requires the matching patched headers/source. Accepted base `.cache/native-vnc/entry-03/` is unchanged and remains a separate native-only result.

The [lock](build.lock.json) binds the exact base receipt and [security/cancellation patch](security-and-cancel.patch). The [helper](../../../../tools/prepare_vnc_adapter.py) verifies the accepted base source/closure before using it, copies a fresh stage, applies the patch, configures JPEG only for its generated header and reuses the actual accepted static JPEG archive. It rebuilds only the patched client and authored JNI; no unchanged JPEG or OpenSSL compilation is repeated. It snapshots authored/transitive build inputs, checks them before publication, records actual compiler commands/logs and rejects changed prepared bytes offline. Build steps use four jobs, 240seconds and 8MiB log limits with the reviewed process-group cleanup. Exact upstream source/archives/notices, matching headers, patched static archive and authored input copies are retained privately in the prepared output. This is not final corresponding-source/distribution approval.


Run from the repository root with the existing SDK and exact accepted base cache. The prepared build instructions depend on the retained accepted base input; recreating its debug-bearing binaries under another path is not claimed byte-reproducible and needs a reviewed pin update. No SDK/system install, listeners, Gradle, credentials or device operation is performed by this entry.

## Security boundary

Only outer **VeNCrypt19 / X509Plain262** is admitted. The patch applies configured top-level policy to RFB3.3 too, and filters VeNCrypt subtypes before writing the selected subtype. Anonymous TLS, X509None, TLSNone, VNC password and unencrypted Plain are not fallbacks. TLS requires at least 1.2, and renegotiation is disabled so the once-per-handshake policy cannot be bypassed by installing a new certificate later.

The accepted upstream fingerprint callback was insufficient: CA preverification could accept a different configured pin, while fingerprint equality could override expiry. With the explicit adapter hook, preverification is deferred to a synchronous unconditional **actual peer leaf DER** callback after `SSL_connect` and before any credentials. DER is capped at 128KiB. Authored [policy.c](policy.c) parses the complete DER without trailing bytes, checks both validity times using nondeprecated `ASN1_TIME_cmp_time_t` (including rejecting its error code), computes standard SHA256 and compares all 32 bytes with `CRYPTO_memcmp`. This is deliberate pinned-leaf trust, not CA-chain/name validation. Credentials are returned only after this policy succeeded and only for X509Plain. The immutable configuration binds that pin to one numeric address, port and nonsecret profile ID. Rebinding/changing pin requires closing/freeing and creating a new explicitly selected profile; there is no TOFU, pin-change approval UI or persistent vault in this ABI.

`GetCredential` uses owned copies, clears the session password after transfer, and the narrow patch wipes the upstream temporary username/password copies before freeing. Native session storage is wiped on free. The Java caller must wipe its own supplied password byte array after `create`; this does not claim erasure of every JVM copy or cryptographic library buffer. No secret/certificate/peer-controlled strings are logged. Upstream log callbacks are suppressed in this dedicated engine process; status uses fixed numeric causes. The patch also releases the successful TLS constructor's context reference retained by `SSL_new`, without changing TLS implementation or certificate parsing.

Official source/API basis: [pinned public client header](https://raw.githubusercontent.com/LibVNC/libvncserver/98aaee0560baa0332339b2ef464ea96ed9b9b28c/include/rfb/rfbclient.h), [upstream security dispatcher](https://raw.githubusercontent.com/LibVNC/libvncserver/98aaee0560baa0332339b2ef464ea96ed9b9b28c/src/libvncclient/rfbclient.c), [OpenSSL TLS backend](https://raw.githubusercontent.com/LibVNC/libvncserver/98aaee0560baa0332339b2ef464ea96ed9b9b28c/src/libvncclient/tls_openssl.c), and [OpenSSL ASN.1 time API](https://docs.openssl.org/4.0/man3/ASN1_TIME_set/), checked 2026-10-15. These describe source semantics, not a successful Android handshake.

## Ownership and ABI

[VncBridge.java](VncBridge.java) declares the actual nine exported JNI entries. All callbacks run synchronously on the sole native worker. They must return promptly, marshal owned copies to UI, and never wait for main-thread work, `join` or `free`. A blocked callback cannot be forcibly terminated safely; a join timeout retains the native owner. Callback Java exceptions are contained, mark failure and stop the worker. No UI is implemented here.

`create` accepts a stable ASCII profile ID (1..64), numeric IPv4/IPv6 address, port 1..65535, exact 32-byte leaf pin, canonical NUL-free UTF8 username (1..256 bytes), password (1..1024 bytes), duration 10..600 seconds and Sink. It returns a non-pointer monotonic handle, or zero on rejection/allocation failure. No DNS resolver or Unix/listen/repeater route is exposed. DNS must be a separately bounded platform operation if later needed; a numeric endpoint profile must be selected explicitly. At most one instance exists in the process, avoiding concurrent use of upstream global initialization/log state.

`start` creates exactly one worker; no reconnect on a started handle. That worker alone calls engine connect, initialize, decode and input methods. Split `rfbClientConnect` / `rfbClientInitialise` APIs preserve explicit cleanup on failure, unlike auto-freeing `rfbInitClient`. Credentials/callback globals survive until actual join/free. A registry reference count protects in-progress JNI calls from free, and stale handles are rejected. `cancel` sets an atomic stop flag and shuts down the mutex-published socket without closing it. Cleanup unpublishes under the same mutex before owning the close, preventing a recycled descriptor race. Cancellation during the initial connect waits for its bounded three-second timeout because the library has not yet published the socket.

The patch checks cancellation/monotonic session deadline in read, write and TLS handshake retry loops, and bounds formerly indefinite plain-write `select`. Read idle timeout is 2 seconds; ordinary event polling is 10ms. These are cooperative I/O boundaries, not forced preemption of arbitrary native decoder CPU work or Java callbacks. `join(timeoutMillis)` is 0..5000ms, rejects self-join, serializes reaping and returns false while ownership remains. `free` throws `IllegalStateException` unless never started or successfully joined and no other JNI call is active. The embedding owner must keep polling join after cancellation, then free off callback/main threads.

Frame dimensions must be positive, each ≤4096 and total ≤8,388,608 pixels (32MiB RGBA). The native worker owns framebuffer/scratch copies; replacement occurs before publishing checked dimensions. `onFrame(handle,width,height,byte[])` receives an independent Java-owned RGBA8888 copy with opaque alpha, so no native buffer survives by Java reference. Native framebuffer, scratch, Java copy, codec buffers and temporary resize overlap are separate allocations; 32MiB is a per-frame bound, not total process RSS. The future UI must coalesce frames and retain a bounded number of Java copies. Frame/decoder code is the actual upstream implementation.

Inputs use a typed 256-entry mutex-protected queue. `pointer` is standard absolute RFB coordinates/button mask 0..255, with bounds checked at enqueue and again on consumption. No relative-input emulation exists. `key` accepts the bounded positive keysym subset up to 0x0110ffff, including core/Unicode keysyms; broader multimedia mapping is not provided. Up to 64 distinct held keys are tracked. A positive return is a sequence for queue admission; zero is rejection, not delivery. `onInputResult` reports the actual upstream send return, which still is not a host acknowledgement. Failed sends stop the session; queued unsent operations complete false before terminal notification. `releaseInputs` queues tracked button releases before modifier/key releases; the UI should wait for that result before planned cancellation. Immediate cancel/transport loss does not promise delivery of releases.

`status` returns `[state,error,frameCallbacks,admittedInputs,completedInputs,successfulWrites,width,height]`. States are 0created/1connecting/2authenticated+initialized/3stopped/4failed. Error causes are 0none/1cancelled/2deadline/3I/O/4certificate/5callback/6frame/7input/8memory/9thread/10security. The first cause wins. Frame counters count callback attempts, not display completion. Closed handles and failed creation cannot be promoted to successful sessions. There is no clipboard, drive/USB forwarding, desktop agent, credential vault or silent authentication fallback API.

## Actual checks and remaining gates

Actual `adapter/entry-02/receipt.json` records successful patched-client static compilation, owned C11 `-Wall -Wextra -Wpedantic -Werror`, undefined-symbol-checked JNI linking, Java17 `-Xlint:all -Werror`, nine actual JNI exports and ELF inspection. `libcloudy-vnc-jni.so` is 3,522,024 bytes, SHA256 `199d99a527305209c8e540c0a137958a51550c90ed523a4f970ed6d0ea941594`; its dependencies are accepted SSL/crypto and Android libc/libdl/libm/libz. Minimum load alignment is 16384; this is not APK alignment or Android loader proof. Initial entry-01's strict owned compile stopped on an OpenSSL4-deprecated time API; the replacement uses the supported API without warning suppression, and that failed input/log is retained. Patched upstream deprecated-API diagnostics remain visible separately from the strict authored build.

Three focused tests pass: changed-input publication rejection, changed prepared output rejection, and the actual authored C policy compiled/executed against host OpenSSL under ASan/UBSan. That executable performs 32 real checks for matching/wrong pin, expired/not-yet-valid leaf, malformed/truncated/trailing/oversized DER, geometry, numeric endpoints, UTF8 and wiping. Test certificates are generated in memory; no user keys or remote protocol responses are used. These do not execute the Android JNI, actual TLS handshake/negative negotiation, native queue, Java callback/lifecycle or physical server paths. Those exact integration cases remain next gates, together with APK packaging and source/license acceptance. The accepted 27 host advisory cases are not rerun or relabeled as this adapter's Android evidence.
