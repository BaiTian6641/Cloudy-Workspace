## Focus, real output, resize and controlled input

Attempt 2 reached an authenticated shell and received its 16-byte prompt, but ADB text with spaces activated the native Disconnect control; the subsequent Enter reached Session details. The terminal journal retained **zero input bytes**. An accessibility node reporting focused did not establish that Android native keyboard focus had moved into the WebView. This failed attempt is retained.

Attempt 3 explicitly tapped the terminal. Rapid bulk text then produced duplicated suffixes and an unmatched-quote continuation; the intended fixture commands had not executed. Injected Ctrl+C returned the shell prompt. Paced character injection subsequently executed the controlled commands. The host measured **205 columns × 32 rows**, `xterm-256color` and `C.UTF-8`. The ANSI helper recorded all **488 expected bytes** written, SHA-256 **`760c9e66310026305b9434d85c974a4f701c63bb1c3eab2ece55ca7ab03effe9`**. The screenshot visibly contains colored ANSI samples, CJK text, combining/precomposed text and emoji. This demonstrates the sampled output, not CJK input or comprehensive Unicode width/font correctness.

The actual curses alternate-screen application received a resize event after the native window was restored to a smaller size. Its final host dimensions were **146 × 23**, matching the terminal's submitted dimensions. It recorded right and down keys, position **x=1, y=1**, then `q` and `tui-quit / intendedExitCode=0`. The screenshot shows the resized application. These are actual curses/ioctl observations, not a predetermined success display.

The controlled raw-input helper captured exactly **12 bytes**, hex **`4142430d031b091b5b417879`**: `ABC`, carriage return, ETX, Escape, Tab, the Up-arrow escape sequence, and `xy`. During attempt 4, the capture helper had reached its wait and the controller observed five owned foreground processes including the listener. After native Disconnect, the journal became closed and a later controller snapshot contained only the original listener identity. The capture's zero-byte `exercise-534beae9…json` file is an incomplete helper record, not a successful empty capture or terminal-restoration receipt. The journal and process observations establish disconnect/cleanup independently of that incomplete record.

Attempt 5 reached open before explicit Activity recreation. The old session became interrupted, with the app PID unchanged. Host authentication/session totals remained unchanged between post-recreation and idle snapshots **12.705553 seconds** apart; the controller retained only the listener. This supports no automatic replay over the observed interval. The early filename `recreate-open-journal.json` actually contains `connecting`; the later event history supplies the open state.

Attempt 6 used an explicit, package/user-scoped **force-stop**. The following observation found no app PID. The unfinished on-disk journal remained byte-identical to the pre-stop journal. Reopening produced a different app PID and marked the retained session interrupted without another authentication/session increase. The exit record matching the old PID reports **reason 10 USER REQUESTED / subreason 21 FORCE STOP**. This is deliberate force-stop recovery, not natural low-memory death, cached-process killing or proof of an in-process cancellation callback. Attempt 7 required a new explicit Connect.

The initially named `recovery7-final-journal.json` still contains `open`; the operator helper had failed before completing the intended exit sequence. The subsequent actual exit and **`recovery7-closed-journal.json`** establish closure. No result is inferred from a filename containing “final.”

After attempt 8, the closed host snapshot recorded **nine accepted public-key authentications and nine session starts**: two host-preflight sessions plus seven authenticated device sessions. The unknown-trust attempt added no authentication. The final app observation contains no named terminal worker threads. At **13:46:48.341517 UTC**, the fixture controller recorded **server exit 0**, connection refused on the selected listener, **zero remaining owned processes**, and **zero forced kills**, across 39 observed foreground process identities. Its scope is the tracked fixture process family, not arbitrary daemon containment. Provider names/order remained unchanged; this does not establish provider implementation-byte identity.

The final eight-attempt journal is full. Preserve/rotate it before another attempt; do not erase this evidence or treat disabled admission as a failed connection.
