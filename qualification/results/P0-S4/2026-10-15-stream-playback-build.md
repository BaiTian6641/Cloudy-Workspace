# P0-S4 — Finite native playback adapter build

**2026-10-15:** streaming diagnostic **0.1.6/code7**, build reference `0e6fd996-6060-4801-9535-99dafac0d3ff`, passes actual Android compilation, 23 JVM tests, scoped Android Lint and package review. **It is not installed or exposed through a playback control.** The installed0.1.5 and its accepted identity/pairing evidence remain unchanged. The [manifest](2026-10-15-stream-playback-build.json) binds source, package, receipts and retained checks. No stream, decoded output, audio or performance result is claimed.

The [real adapter and exact patch](../../probes/native-stream/playback/README.md) reuse the pinned Moonlight connection, native media transport, MediaCodec renderer and AndroidAudioRenderer. It does not introduce a replacement decoder or protocol. The preparer composes the new overlay after the frozen pairing overlay, verifies its prerequisite hash and every before/after target hash, and freezes seven new production classes plus the policy tests. The accepted native engine is unchanged.

The first preview requests 1280×720 H.264 SDR at60fps and10,000Kbit/s with stereo audio, no controller negotiation and fixed local transport. An immutable selected numeric IPv4 peer, ports, application ID and public server certificate/pin constrain requests. Server information, launch and resume use pinned HTTPS only; there is no HTTP fallback, redirect/retry or automatic quit of another running application. Returned RTSP endpoints must match the selected peer/port. Actual UDP/RTSP/ENet routing remains a device/host test; the previous TCP ADB pairing route does not establish it.

Fresh device-credential type1 authorization must qualify the existing identity and supply the provider on the same attempt. Setup and playback together are clipped to **30 seconds from the original callback**, with real call cancellation through body close and a native cancellation watchdog. Native startup resets its interrupt flag; the adapter reasserts cancellation at the first stage callback and through the watchdog. This is cooperative cancellation, not a guarantee that arbitrary native/codec work can be forcibly preempted.

Review caught a double-release/partial-setup defect before acceptance: native stop already invokes decoder cleanup, followed by owner cleanup. The corrected actual decoder cleanup is null-safe and idempotent; controlled stop waits for its real renderer/Choreographer threads before completion. Failed or blocked cleanup retains ownership. The parent must retain its Surface until actual retirement. Metrics are cached before clearing Activity/decoder/engine references, and watchdog retirement prevents old cancellation from reaching a replacement.

The retained native core has a detached asynchronous termination callback and a process-global Java bridge. This bounded increment consequently permits **one playback run per process**, including preparation failures. Release does not reset that restriction. A fresh process and explicit durable reconciliation are required before another preview. This is a qualification limit; repeated product sessions remain unresolved. No speculative native rewrite was added.

The actual EGL query returns driver renderer metadata or an explicit unknown value. The balanced initialization/termination relies on Android's [AOSP display reference counting](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/main/opengl/libs/EGL/egl_display.cpp), not a portable EGL guarantee; the exact vendor implementation and runtime remain unverified. Codec identity and `isHardwareAccelerated()` are actual platform metadata, not a benchmark. Submitted decode units, released output buffers and rendered callbacks are separate counters. [Android's rendered callback contract](https://developer.android.com/reference/android/media/MediaCodec.OnFrameRenderedListener) allows delayed/batched dispatch, so counters do not establish visible pixels or input-to-photon latency.
