## Implemented boundary

The native TextureView supplies a real Surface to the frozen `PlaybackController`; there is no fabricated video, connection or frame result. An explicit preview action requires a READY app-owned identity, private immutable `no_backup/playback-config.json`, local-network permission and a fresh credential-only system prompt. Actual authentication type 1, identity qualification, provider acquisition and playback share the same live attempt and original 30-second authorization window. The profile selects the numeric LAN peer, exact public certificate/pin, distinct HTTP/HTTPS/RTSP ports and real application ID. It does not discover an application, establish route reachability or approve a replacement peer. Selected application discovery and a qualified media route remain prerequisites to runtime activation.

The frozen engine requests bounded 1280 × 720 H.264 SDR video and stereo audio through actual Moonlight/MediaCodec/audio APIs. It uses fixed local transport, pinned HTTPS control, no HTTP fallback and no automatic replacement of another host application. The UI exposes actual controller phase/failure, codec metadata, decode-unit submissions, buffers released for rendering and frame-render callbacks separately. These are available runtime measurements, not observations made by this build checkpoint. Input forwarding is outside this preview increment.

Identity, pairing, reconciliation and playback share one process owner. Real backgrounding, operator cancellation, authorization expiry, owner clearing or matching surface destruction revoke the attempt and cancel the published controller. Configuration recreation also destroys/cancels playback; it never rebinds the old decoder or automatically starts a new preview. Prompt recreation only reattaches its original callback token.

The release chain is explicit: the worker returns and the actual controller retires; the old TextureView is detached; its matching destruction callback transfers ownership by returning false; the main thread releases Surface and SurfaceTexture; then the worker writes and reads back terminal evidence. Only after all those conditions may the process lease be released. Cleanup or evidence failure retains ownership and exposes a retry for that same owner. An unused CREATED snapshot is not retirement evidence while a worker can still publish an engine. The frozen engine permits **one native playback run per process**, including preparation failures after run admission; release never resets that restriction.

Both pairing and playback scan both network journal directories before either network action. A durable pending reservation precedes network work. Malformed, unfinished or evidence-unavailable prior records block new network admission. The explicit reconciliation action can acknowledge only well-formed records from a different process, binding their exact SHA256 bytes in a separately written/read-back receipt. It preserves original records, records host state as UNKNOWN, and never replays a launch, unpairs a host or claims remote shutdown. Atomic-file residue and malformed records require deliberate private-file repair. A process restart alone does not close them.
